# RcloneView 1.7 – Release Notes

**Release Date:** November 2026<br/>
**Platforms:** Windows, macOS, Linux

RcloneView 1.7 takes Batch Jobs out of beta and adds import and export of remotes, with an undo for a recent import. Several settings that rclone had been quietly ignoring now do what they say — a job's retry count, the delete timing of a sync, one-letter and local-disk Custom flags, and the options of batch Check and empty-folder steps — so please read the first section before upgrading. This release also lets you run a job straight from its *Dry Run* preview, redesigns Mount Manager as a table that shows why a mount is not working, rebuilds the mount window with every VFS option and a *Media streaming* kind, adds a *Detect renamed files* option for Sync, shows start and completion times in the Transfers tab, and hides system files in the explorer by default. Uploads to Google Drive now stop at the daily limit instead of retrying for days, macOS mounts that hang while unmounting no longer hold up the app, and very large previews no longer freeze it. Alongside those, this release fixes a long list of problems in transfers, mounts, the explorer, multiple windows, licensing, and the Linux packages.

## Please Read Before Upgrading

- **Batch Jobs now need PLUS, with a 7-day trial.**
  Batch Jobs are out of beta and are now part of PLUS. On a free license, adding, opening, editing, duplicating,
  previewing, and running a batch now ask for PLUS; until now only scheduling a batch did. On a free license, Batch Jobs
  open for 7 days on this computer from the first time this version runs. Your batches are not deleted when the trial
  ends: they stay in Job Manager, locked, and open again once a PLUS license is registered.

- **Importing and exporting jobs and remotes needs PLUS, with a 7-day trial.**
  Job *Import* and *Export* in Job Manager, free until now, are now part of PLUS, and so is the new import and export of
  remotes in Remote Manager. On a free license each of them opens for 7 days on this computer from the first time this
  version runs. *Undo a recent import* and *Where are my remotes saved?* stay available on every license.

- **Sync and Copy jobs now try again after a failure.**
  A job's *Retry the entire operation if it fails this many times* setting (3 by default) and `--retries` /
  `--retries-sleep` in its Custom flags never did anything: rclone reads them only when it runs from the command line,
  so every job ran exactly once. RcloneView now runs a failed Sync or Copy job again itself, by the same rules as the
  rclone command line: only when rclone considers the errors worth retrying and none of them is fatal, up to that number
  of attempts in total, and waiting `--retries-sleep` between attempts. A cancelled run, or one stopped because a
  remote's sign-in was rejected, is not retried. History, notifications, and email report the run once, after the last
  attempt.<br/>
  **This changes what existing jobs do.** A job that fails now takes longer to report it, because by default it is tried
  three times, and a run that failed because of a passing problem may now complete. To keep a job to a single attempt,
  set the value to 1. Bisync jobs are not affected.

- **Uploads to Google Drive now stop at the daily upload limit.**
  Google Drive accepts about 750 GB of uploads per account per day. rclone treated that limit like an ordinary rate
  limit and kept retrying, so a large job could stay "running" for days without uploading anything, and in the end
  showed only a general error. The rclone bundled with RcloneView now stops as soon as the limit is reached, and a job
  that hits it ends with a message explaining the limit. Run the same job again once the limit resets, usually within 24
  hours: files already copied are skipped.<br/>
  **This changes what long Google Drive jobs do:** they now end with an error at the limit instead of waiting it out.

- **The explorer now hides system files and leaves them out of its copies.**
  A new setting, *Hide system files* in *Settings → Interfaces & Notifications*, is on by default. It hides
  `$RECYCLE.BIN`, `System Volume Information`, `desktop.ini`, `Thumbs.db`, `pagefile.sys`, `hiberfil.sys`,
  `swapfile.sys`, `.DS_Store`, `.Spotlight-V100`, `.Trashes`, and `.fseventsd` in the explorer, and leaves them out when
  you copy and paste, drag and drop, upload, or download in the explorer. Jobs, Compare, moving, and renaming are not
  affected. If you copy whole drives in the explorer and need those files at the destination, turn the setting off. Job
  filters also get a *System files* group, off by default, to leave the same files out of a job.

- **Custom flags and batch options that did nothing now take effect.**
  The following were sent to rclone in a form it discards, so they had no effect. They now work, which changes what jobs
  and batches that use them do:
  - `--delete-before` and `--delete-during`, in Custom flags or as a batch step's delete-timing chip: a sync always
    deleted after transferring. A job or step with more than one of `--delete-before`, `--delete-during`, and
    `--delete-after` now refuses to run, as rclone itself does, and a batch step allows only one of those chips.
  - One-letter flags such as `-c`, `-u`, and `-M` were dropped without a warning, and a one-letter flag after a flag
    that takes no value was read as that flag's value, so both were lost. They are now expanded to their long names; a
    one-letter flag rclone does not have is left out with a warning.
  - `--copy-links` (`-L`), `--skip-links`, `--one-file-system` (`-x`), and `--skip-specials` now apply to the local
    source or destination of the job; on a cloud side they do nothing, and the warning says so. With `--copy-links`, the
    files that symbolic links point to are now copied.
  - `--metadata-include`, `--metadata-exclude`, `--metadata-filter`, and their `-from` forms.
  - A batch *Check* step's `--one-way`, `--download`, `--size-only`, and `--fast-list` chips and its *Additional flags*.

  Flags that rclone reads only from the command line, such as `--error-on-no-transfer` and `--progress`, now show a
  warning that they have no effect. Please run affected jobs and batches once with *Dry run* before letting them run on
  a schedule.

- **Batch empty-folder chips now decide what happens to empty folders.**
  The `--create-empty-src-dirs` and `--delete-empty-src-dirs` chips on batch steps did nothing either way: *Copy Folder*
  and *Sync* steps always recreated empty source folders at the destination, and *Move* steps always did that and also
  removed the source folders they emptied. Each step now does this only when its chip is on, in batches you have already
  saved too.<br/>
  **This changes what existing batches do.** If you rely on empty folders being copied, or on a Move step cleaning up
  the folders it empties, turn the chip on in those steps. *Rename* steps always move the whole folder, and their
  `--delete-empty-src-dirs` chip has been removed.

- **A batch Delete step with `--rmdirs` now removes empty folders.**
  `--rmdirs` on a *Delete* step was ignored when the batch ran; only the preview showed the folders being removed. After
  deleting files, the step now also removes the empty folders left under its path, keeping the step's folder itself. The
  step's include and exclude rules apply to this; folders that still hold files — newer files kept by `--min-age`, for
  example — are left alone. The *Cleanup history* template uses this option. If you expect empty folders to stay after a
  Delete step, remove `--rmdirs` from it.

- **Batch steps that used to pass can now fail.**
  A *Check* step counted only files missing on one side. Files whose contents differ, and a check that could not run at
  all, now fail the step, so the step's *Error policy* decides what happens next (see Data Loss below). The step also
  gains the outputs `differ` and `error_files`. A step that uses the output of an earlier step that produced none — for
  example `{{step1.differ}}` after step 1 failed and was skipped — used to run with that text as written, creating a
  folder with that name; it now fails with *Not run* and the reason. If a batch is meant to continue past a Check step,
  check that step's Error policy.

- **Do not go back to 1.6 after this update.**
  This update changes the database format again, so that it can record when each transfer finished, when each mount last
  failed, and each mount's kind and VFS settings. If an earlier version opens the database afterwards, it deletes it and
  starts with an empty one: your jobs, batches, job history, saved mounts, and filter presets are lost. Remotes and
  settings are not affected. If you may need to go back, keep a copy of `rclone_view.db` from the *Database folder*
  shown in Settings before updating.

## Data Loss and Security

- **A Batch Check Step Passed When Files Differed:**
  A *Check* step treated files with different contents as matching, and a check that failed — a remote error or a
  timeout — as finding no differences. A batch that checks a copy before deleting or moving the source could therefore
  go on to remove source files whose copy did not match or was never checked. The step now fails in both cases. If you
  have a batch that runs a Check step before a *Delete*, *Purge*, or *Move* step, make sure the destination holds
  complete copies of what was removed from the source.

- **A Leftover Drag Could Copy or Move Folders on the Next Click:**
  A click with a slight mouse movement starts a drag. When another window — a provider's sign-in page in the browser, a
  secondary window, a system dialog — took the mouse before the button was released, the drag stayed alive, and the next
  click, often in the other pane, dropped it there. This copied or moved the folders open in the first pane without
  anything being dragged. It was seen after signing in to a provider, entering a license key, editing a remote, and
  adding S3, B2, or Mega remotes. A drag interrupted this way is now ignored. If a transfer you did not start appeared
  in the Transfers tab after one of these steps, check both folders.

- **A Batch Step Changed to Rename Could Move Only Part of the Folder:**
  Changing a step's operation kept the old operation's filter and transfer values, hidden, along with all of its chips.
  A *Move* step with a *Min age* filter that was changed to *Rename* kept the filter, so the rename moved only the
  matching files to the new name and left the rest in the old folder. Changing the operation now keeps only the options
  the new operation offers, and a Rename step never applies filters, including in batches already saved. If you have a
  Rename step that was once a different operation, check that nothing was left behind under the old name.

## Highlights

- **Batch Jobs Leave Beta:**
  The Beta label is gone, and batches gain: *Retry Failed Steps* — after a failed run, the run window carries on from
  the failed step, passing on the outputs of the steps that finished. A failed run can also be retried from the batch's
  history: steps that finished are skipped, earlier steps whose output a later step needs run again, and the list of
  steps is shown before anything starts. Steps finished in an earlier run are not repeated when that retry is retried in
  turn. *Run in background* — the run window no longer blocks the rest of the app while a batch runs. Close it with *Run
  in background*, follow the batch in the Transfers tab, and a message at the bottom of the window says when it has
  finished or failed. Pressing *Run* on a batch that is already running reopens its window instead of starting a second
  run, and a manual run and a scheduled run of the same batch no longer overlap. *Update existing files only* — a new
  option for Copy steps that copies only files that already exist at the destination, so files you have not downloaded
  stay in the cloud. The new *Files-on-Demand (Offline Cache Sync)* template uses it to keep a local offline folder and
  a cloud folder in step.

- **Import and Export Remotes (PLUS):**
  Remote Manager has a new menu for backing up and restoring remotes. *Import remotes from a file…* reads an rclone
  configuration file and shows which remotes are new, which are already in your list unchanged, and which have the same
  name but different settings; you choose which to add. For a name that is already taken, pick *Keep mine* (the
  default), *Use imported*, or *Keep both*, which imports it under a free name such as `name-2`, and *See what's
  different* lists the settings that differ, with passwords and tokens hidden. A file encrypted with a configuration
  password is refused with an explanation. *Export remotes to a file…* saves your remotes, optionally leaving out
  passwords and tokens so the file is safe to share. *Undo a recent import* puts back the remotes an import changed:
  before every import RcloneView keeps a copy of the remotes it is about to touch, in the app's secure storage rather
  than a plain file. *Where are my remotes saved?* shows the configuration file's location and copies its path. Import
  and undo are unavailable while connected to an rclone that RcloneView did not start. If your own rclone configuration
  is encrypted with a password, import and export still work and the configuration stays encrypted where it is.

- **Mounts That Hang While Unmounting No Longer Hold Up the App (macOS):**
  On macOS, rclone can get stuck unmounting a mount, waiting on a system unmount command that never finishes. Unmounting
  then took 30 seconds and ended as *unmount failed*, *Unmount all* took about a minute, the list kept showing the mount
  as mounted, and quitting left rclone and that command running in the background. Unmounting now falls back to the
  system's own unmount after about 12 seconds and updates the list straight away, *Unmount all* no longer keeps asking a
  stuck rclone, and Mount Manager shows progress while it works. On quitting, a stuck rclone and the unmount commands it
  started are stopped — those processes only, picked by their process id.<br/>
  On every platform, while rclone has not finished an earlier mount request, every new mount waits behind it. The app
  used to say the mount would appear "once it is ready" and send another request each time you tried again. It now says
  that rclone is busy with another mount, stops sending new mounts until rclone answers again, and offers *Restart
  Embedded Rclone* — first telling you how many mounted drives and running transfers the restart will stop.

- **Large Previews No Longer Freeze the App:**
  A dry run that lists hundreds of thousands of lines — a whole home folder, for example — froze the app. Large previews
  no longer do: the Wizard lists up to 500 rows while its totals still count everything, a batch's detail log keeps up
  to 5,000 lines, and the error dialog shows up to 100 error lines. *Cancel* now stops a running job, Wizard, or batch
  preview at once, a long preview that keeps producing output runs to the end, and a preview gives up only after rclone
  has sent nothing for five minutes. Paths containing `{` or `}` no longer break preview lines. Also fixed: a loading
  overlay could stay on screen after connecting in Connection Manager, testing a connection, or checking for rclone
  updates, blocking every click; and Remote Manager asked every remote for its details over and over while it was open.

## New Features and Improvements

- **Run Straight From a Dry Run:**
  When a job's *Dry Run* finishes, the preview now offers *Run* next to *Cancel*. *Run* starts that same job — with the
  job's own filters and options, exactly as the preview saw them — just as the *Run* button does: if the job is already
  running, you are asked before it starts again. In the one-time Sync/Copy dialog, the preview uses the form as it is,
  without saving it, and the dialog closes once the job starts. While you add or edit a job, the preview still ends with
  *OK*, since those windows end with *Save*.

- **Mount Manager Redesigned:**
  Mount Manager now lists your mounts in a table with *Status*, *Source*, *Mount point*, *Method*, and *Auto* columns,
  and a summary line such as *5 mounts · 3 mounted · 1 need attention*. Mounts that need attention come first — *Error*,
  then *Disconnected*, then mounts in progress, then *Mounted* and *Not mounted* — and you can sort by status, source,
  or mount point by clicking the column header. *Error* — when a mount fails, its row shows rclone's reason and the time
  it failed, and its button becomes *Remount*. An automatic mount that fails when the app starts is now recorded the
  same way; until now it was only written to the log. *Disconnected* — a mount with *Auto mount* on that is not mounted,
  for example after rclone was restarted, is marked as such and also offers *Remount*. A mount you unmounted yourself is
  shown as *Not mounted* instead, until the app restarts. Each row's ⋯ menu offers *Open folder*, *Copy path*, *Edit*,
  *Duplicate*, and *Delete*. *Duplicate* opens the New Mount window with the same settings and an empty mount point.
  *Edit* and *Delete* are unavailable while the mount is mounted or still mounting or unmounting, and the menu says to
  unmount it first. Mount Manager no longer shows a message after every successful mount, unmount, or delete; failures
  are still reported.

- **Mount Window Redesigned:**
  The window for a new or edited mount now starts with two kinds to choose from: *Standard*, for opening and saving
  files such as documents and photos, and *Media streaming*, which fills in cache and read-ahead values so Plex,
  Jellyfin, and video players can read videos without stuttering, and mounts read-only. Its maximum cache size is worked
  out from the free space on the cache drive. Values you change from what the kind fills in are marked, and Mount
  Manager tags media mounts with *Media streaming*. The settings are grouped on the left — *Basic*, *Cache*, *Playback*,
  *Folder listing*, *Writing*, *Permissions*, and *Other* — and every rclone VFS option, plus `--attr-timeout`, now has
  its own field. An empty field shows rclone's current value in grey, and values are checked the way rclone checks them.
  When the same option is also in Custom Flags, the field says *Overridden by Custom Flags*, and the Custom Flags value
  is used. Under *Mount location*, the window shows where the mount will actually appear, and on Windows, what Explorer
  will call the drive. *Browse* is now available for the remote path, and on macOS and Linux for the mount location too.
  *Refresh new files* (off, or every minute up to every hour) makes a mount show files added on the remote without
  waiting for its folder cache to expire — useful for remotes that do not report changes, such as SFTP or WebDAV. If
  refreshing keeps failing, or another mount uses the same source, the mount's row in Mount Manager says so. For *Media
  streaming*, the number of parallel reads (`--vfs-read-chunk-streams`) depends on the kind of remote: 8 for PikPak,
  Proton Drive, and Filen, whose single connections are too slow for smooth playback, and 0 for the others, which open
  and seek faster that way and use far less memory. A Crypt or other wrapping remote is judged by the remote it wraps,
  and the value follows when you pick another remote unless you changed it. The window warns when parallel reads are set
  high enough to use much more memory in the app's rclone.

- **Detect Renamed Files:**
  One-way Sync jobs have a new *Detect renamed files* option (`--track-renames`), and batch Sync steps offer it as a
  chip: files renamed or moved in the source are moved on the destination instead of being uploaded again. Where the two
  sides share no hash, as with Crypt or SMB, files are matched by name, size, and modification time. A warning appears
  when the option is combined with Copy or Move, where rclone ignores it, or with `--delete-before`, which rclone
  refuses.

- **Start and Completion Times in the Transfers Tab:**
  The Transfers tab has new *Started at* and *Completed at* columns, with the full date in a tooltip. Completion times
  are saved, so they are still shown for past transfers after the app restarts; transfers recorded before this update
  have none. A file that is waiting or still being transferred shows no completion time.

- **Waiting Between Retries Shown in the Transfers Tab:**
  While a job waits to try again, the last row of that run shows *Retrying in 30s*, counting down, with an ✕ that
  cancels the whole run so that no further attempt starts.

- **Clearer Connection Errors in the Wizard:**
  For WebDAV and SFTP, the Wizard's *Verify* step now names the problem — such as *Sign-in failed*, *Access denied*,
  *WebDAV folder not found*, *Cannot connect to the server*, *Server not found*, *Secure connection failed*, or *The
  server's identity has changed* — and says what to check, with rclone's original message under *Show details*. A
  failure to reach the server at all is now shown at the *Connect* step instead of *Authenticate*, and on Windows a
  refused or timed-out connection is recognized as one.

- **Fixing a Sign-In Failure From a Mount or Job:**
  Since 1.6, a remote whose sign-in was rejected is not contacted again until you press *Retry*, but that button was
  only in the explorer. Mounting such a remote from Mount Manager or the New Mount window used to show the old rclone
  error as if it had just happened, and running a job from a window showed only a one-line message. Both now explain
  that RcloneView did not connect this time, give the earlier reason, and offer *Edit Remote* and *Retry*; once the
  sign-in works, the mount or the job carries on. The *Sign-in failed* badge in Remote Manager opens the same window.

- **Google Photos as a Source:**
  Google Photos only lets RcloneView read photos uploaded with the remote's own client ID, so copying a library filled
  from the Google Photos app or website transfers nothing. The job dialog, the Wizard, and the batch editor now say so
  when a Google Photos remote is chosen as the source, with a link to Google Takeout for copying a whole library. The
  notice shown when creating a Google Photos remote was rewritten the same way and no longer tells you to run rclone
  commands.

- **Your Own Client ID Recommended for Google Drive:**
  A Google Drive remote without a `client_id` signs in with rclone's shared client ID, whose request limit many users
  share, so it can be slow or fail with 403 errors. When the `client_id` field is empty, New Remote and Edit Remote now
  say so, with a link to *How to create your own client ID*; the Wizard, which has no such field, says it can be added
  later with *Edit Remote*. A remote can still be saved without one, and remotes that use a service account are not
  affected. The mount window shows the same advice for a *Media streaming* mount of such a remote, also through Crypt or
  another wrapping remote.

- **Retry a Cancelled Transfer:**
  A copy, move, upload, or download you cancelled in the explorer now has a *Retry* button, like a failed one. Its
  tooltip explains that files already copied are skipped and a file that was in progress starts over. A transfer
  cancelled while it was still checking files is now shown as *Canceled* instead of *No Changes* or *Success*.

- **Transfer Groups Stay the Way You Left Them:**
  An expanded transfer group no longer collapses when you change the filter or another transfer finishes, and new and
  past transfers now open the same way. A new setting, *Show transfer groups collapsed*, shows only the group rows; it
  is off by default.

- **Remote Cards in the Explorer:**
  The remote cards in an explorer pane now have an *Edit* button, which opens Edit Remote, next to *Open*, and show the
  same storage chart as Remote Manager. The chart grows with the card, *Free* is shown in green, and a percentage that
  does not fit on the ring is left out; the legend still lists every value. Long remote names and legend entries are
  shortened with "…" instead of wrapping in the middle of a word.

- **Finding the rclone Log:**
  *Settings → Embedded Rclone* has a new *Open log folder* button next to *Log folder*. It opens the folder with the log
  file selected (on Linux, the folder), or says that the folder does not exist yet. On Windows, the default log folder
  is now your actual Documents folder — the one File Explorer shows, also when Documents has been moved to OneDrive —
  instead of always `%USERPROFILE%\Documents`, where the log could not be found. A log folder you set yourself is not
  changed, and the app's own log stays in its earlier default folder.

- **Compatible DNS Mode (macOS):**
  With iCloud Private Relay on and a remote that uses plain HTTP (Mega, for example), rclone on macOS can lose the
  ability to start new tasks, so mounts and previews never finish. RcloneView now detects this and explains it, with a
  button to restart rclone in the new *Compatible DNS mode* (*Settings → Embedded Rclone*, off by default). In that mode
  names ending in `.local` and names only your VPN knows are not found, and the app points this out when such a name
  fails.

- **Opening Settings With ⌘, (macOS):**
  ⌘, now opens General Settings, as in other Mac apps, when no dialog or menu is open.

- **Start-Up Problems Explained:**
  When the bundled rclone is missing, the start-up message now says *Rclone executable not found* and suggests
  reinstalling or allowing RcloneView in your antivirus, instead of a general *No valid connection*. On Windows, an
  error before the window opens is now shown in a message box with the location of a log file and what to try, instead
  of leaving a hidden process behind; and starting RcloneView while an earlier copy is running but not responding now
  says so and explains how to end it, instead of doing nothing.

- **What's New in RcloneView Mobile 1.1:**
  The *RcloneView Mobile* window now shows what the mobile app's 1.1 update adds — streaming, copy and sync between
  clouds, and freeing up phone space after photo backup, all part of Plus — with a short video you can jump through by
  scene. It has QR codes and buttons for both Google Play and the App Store, and *Send remotes to phone* moves this PC's
  remotes to the phone with one scan. The window opens once by itself after the update, also if you chose *Don't show
  again* for the earlier announcement; choosing it again hides the menu bar button, and *Help → RcloneView Mobile* still
  opens the window. The video is downloaded from rcloneview.com once and plays from a temporary copy; when the window
  opens by itself it waits until the video is ready. Without an internet connection the window shows a picture of the
  new features instead.

## Bug Fixes

### Jobs, Batches, and Transfers

- **Running a Job Again While It Was Running:** Pressing *Run* on a running job and choosing *Proceed* cancelled the
  running copy but never started the new one, and the cancelled run showed a "Job N error" dialog, which then closed
  instead of Job Manager. The app now waits for the old run to stop before starting again, says so if it does not stop
  in time, and records the cancelled run as *Canceled*.

- **Closing a Dry Run Error Closed Job Manager:** Closing the error dialog of a dry run also closed Job Manager or the
  Sync/Copy dialog underneath it.

- **The Folder Depth Error Closed by Itself:** Running a job with *Don't process folders over this depth* turned on and
  the box empty showed its error message for an instant and closed it, as if the job had started.

- **Empty rclone Windows During Dry Runs and Scheduled Bisync (Windows):** Every dry run opened an empty console window
  titled rclone, and closing that window stopped the dry run. A bisync job that finished in under 5 seconds, as
  scheduled runs often do, also flashed an empty console window for a moment, even with `--no-console` set.

- **Short Bisync Runs Ran Twice:** A bisync job that finished in under 5 seconds — as a scheduled bisync with nothing to
  do usually does — was run a second time straight afterwards to collect error details, even when it had succeeded. That
  second run was a real bisync: files changed in between were transferred without showing in the progress or in History,
  a job with resync turned on resynced again, and a bisync cancelled within 5 seconds started again. The second run now
  happens only when the first one failed, so its error message is still shown.

- **A Stray Comma Made a Schedule Run Every Time:** A schedule field left ending in a comma, such as `5,`, was cleared
  when the job was saved, which means "every". A number in the middle of a list such as `1,2,3` could not be deleted
  either, and in a batch the leftover `1,,3` was saved as is and refused by the scheduler. Empty parts are now removed
  (`1,,3` becomes `1,3`), and the batch editor shows the tidied value after *Simulate* or *Save*.

- **Monthly Schedules in the Preview:** The list of upcoming runs showed only 3 runs for a schedule that runs once a
  month, instead of 10.

- **Scheduled Batches Overlapped:** A scheduled batch whose run took longer than its interval ran again as soon as it
  finished, or a second run started alongside it. Schedule times that pass while a run is still going are now skipped.

- **Jobs Changed Through the Web Server:** Creating, changing, or deleting a job through the web server's API did not
  update the schedules until the app restarted: new schedules did not run, changed ones ran at the old time, and deleted
  jobs kept running.

- **Bots Said "Started" When Nothing Started:** The Telegram, Slack, and Discord bots answered *Started job* even when
  the job did not start because it was already running or a remote's sign-in had failed. They now say why the job did
  not start.

- **Duplicate Job Names:** *Duplicate* in Job Manager could give the copy a name already used by a job of another
  connection, after which saving it failed with "Job name already exists", and a copy of `Job (1)` was named `Job (1)
  (3)`. Names that differ only by spaces at the start or end could also both be saved.

- **Batch Dry Runs Said "No Changes":** The preview of a batch *Delete* or *Purge* step listed the files it would delete
  and still said there were no changes, and the preview of a *Move* within one remote showed no changes at all.
  Cancelling a batch dry run showed *Complete — no changes needed*; it now says how many steps were not checked.

- **A Cancelled Batch Was Saved Twice:** Cancelling a batch run saved it to history twice, once as cancelled and once as
  failed.

- **`--dscp` and `--metadata-set` in Custom Flags:** `--dscp` is now read as rclone reads it, as a number from 0 to 63
  or a name such as `AF21`. A number such as 18 used to set a different value, and a name was dropped as "not a number".
  Keys given with `--metadata-set` are now sent in lower case, as rclone does.

- **Bandwidth Limit Between Two Local Folders (macOS):** A batch Copy or Sync step between two local folders ignored its
  bandwidth limit, because macOS copied the files itself. With a limit set, those steps now copy through rclone and keep
  to it.

- **Copied Files Shown as "No Changes":** Small files that rclone 1.75 had actually copied were shown as *No Changes* in
  the transfer details.

- **Uploads Stuck at "Queued":** An upload over an existing file of the same name stayed at *Queued* and 0% for the
  whole upload, and an empty file stayed *Queued* and then showed *No Changes*.

- **File Names Cut Short in Transfer Details:** A file whose name began with the name of the destination folder lost
  that part — `support-sitemap.xml` was shown as `-sitemap.xml` — and a transferred empty file showed 0%.

- **Backup Copies Listed as Transferred:** In a sync with a backup folder to storage that cannot move files on the
  server, files moved into the backup folder were listed as transferred, and the job details said only part of the list
  was shown when nothing was missing.

- **Folder Name Repeated in the Source Column:** A failed or cancelled folder transfer showed its source as
  `…/big/big/big`, adding the name again on every refresh.

- **Earlier Transfer History Disappeared:** rclone numbers its jobs from 1 again each time it starts, and a new run with
  the same number deleted the earlier run's transfer records. When an rclone that RcloneView did not start was restarted
  at the same address, runs from before and after the restart were also mixed up.

- **Maximizing the Transfers Panel:** Restoring the maximized Transfers panel switched both explorer panes back to their
  first tab, so a Sync started afterwards picked up those tabs, and the transfer list jumped back to the top.

### Mounts

- **Mounted Drives Marked as Unmounted (Windows):** While rclone was busy with a mount and did not answer, drives that
  were still mounted were recorded as unmounted. This also happened when connected to rclone on another machine.

- **Unmount Failures From the Tray:** A failed unmount from the tray menu showed nothing; it now shows a system
  notification. *Unmount all* no longer shows an error dialog when rclone is merely slow to answer, and checks whether
  the drives are actually gone.

- **Empty Folders Left Behind by a Failed Mount:** When a mount failed, the empty mount-point folder RcloneView had
  created for it stayed behind. It is now removed; folders that existed before are left alone.

- **Absolute Paths on a Named Local Remote (macOS and Linux):** Mounting a path such as `/home/me/x` from a named local
  remote mounted `/home/me/x` inside your home folder instead — an empty folder that was shown as mounted. RcloneView
  now checks which folder exists, and fails with *Folder not found* if neither does.

- **More Mounted Local Remotes Listed as "Configured" (Windows):** A local remote named exactly `local`, a mount of a
  local drive's root or of a relative path, and an alias such as `loc:C:` were still listed as *configured* while
  mounted.

- **Mount Folder Name Already in Use (Windows):** Mounting the same remote again in the same place suggested the same
  folder name and failed with a general "already exists" message. Mount Manager now says where the name is taken and
  offers a free one, such as the remote's name followed by the folder being mounted.

- **Empty Mount Point Saved (macOS and Linux):** A mount could be saved with an empty mount-point folder, which could
  leave `/` as its mount point. The New Mount and Edit Mount windows now ask for a folder name before saving.

### Explorer, Compare, and Filters

- **Unreadable Local Folders Looked Empty:** A local folder your account cannot read was shown as an empty folder. It is
  now shown as a folder that could not be loaded, with advice about disk access and permissions, also through an alias
  or Crypt remote.

- **The Folder Picker Showed Only "/":** When the top folder of a remote could not be read — a server that was off or
  refused the connection — *Select Remote & Folder* and the folder pickers of mounts and batch steps showed a single
  `/`, like an empty remote. They now show *Couldn't load this folder* with *Retry*.

- **The Folder Picker Picked the Previous Remote's Folder:** Switching remotes in *Select Remote & Folder* before the
  previous one had finished loading could fill the list with the previous remote's folders and select one of them.

- **Typing a Path on the Local Disk Tab (Windows):** After moving to a folder on another drive by typing it in the path
  bar, Compare, Sync/Copy, and Job Manager used the first drive of the tab with that path and failed with "directory not
  found".

- **New Folder Reported Success When Nothing Was Created:** The Log said "completed successfully" as soon as rclone
  accepted the request, even when creating the folder then failed. On storage that cannot keep empty folders, such as B2
  and S3-compatible storage, the folder was never created while everything said it was. The Log now records the actual
  result, and in that case the row shows *Failed* with an explanation that the folder appears once a file is put in it.

- **Renaming Duplicates:** Renaming files with duplicate names ran without your rclone configuration file and global
  flags, and was reported as done even when it failed. Failures are now shown.

- **The Folder Tree After Rename or New Folder:** After renaming or creating a folder, the folder tree could show the
  old contents and collapse expanded folders, and the file list could stay on its loading indicator when the rename did
  not start.

- **Compare Listed Filtered-Out and Empty Folders:** Compare results kept showing folders whose files were all excluded
  by the filter, and a row for every intermediate folder that holds no files itself.

- **Compare Copy Never Finished:** When rclone could not be reached while copying from the Compare view, the rows never
  completed and the window stayed in its transferring state. After three failed status checks in a row, the affected
  rows are now marked failed and the copy moves on.

- **Choosing a Folder of an Alias Remote in Compare:** The folder picker opened an empty tree for an alias remote, and a
  folder picked there came back under the name of the remote the alias points to.

- **"Others" Stayed Checked in Filters:** Removing the only rule under *Others* in the job or Compare filter tree left
  *Others* checked with nothing under it.

### Remotes and Signing In

- **Saving a Remote Interrupted Other Remotes:** Adding, editing, or deleting a remote cleared rclone's cache for every
  remote, which could interrupt transfers and mounts on other remotes. The whole cache is now cleared only when another
  remote — a Crypt or Union remote, for example — or an alias depends on the one that changed.

- **Changes to the Configuration File Were Missed:** RcloneView stopped noticing changes made to `rclone.conf` outside
  the app if the file did not exist yet when the app started, after it was deleted and created again, and after *Update
  Rclone*. Changes made while the app was saving a remote itself could also be lost. While connected to an rclone that
  RcloneView did not start, the file is no longer compared.

- **Sign-In Failures Shared Between Connections:** A remote with the same name on two rclone connections shared one
  sign-in record, so a failure on one connection blocked the working remote on the other, and a check passed on one was
  trusted on the other. Each connection now keeps its own.

- **Oracle Object Storage Private Key Not Found:** When `key_file` in the OCI configuration is a bare file name or a
  relative path, rclone inside RcloneView cannot find the key. The error screen now explains this and how to fix it:
  write the full path, restart the embedded rclone, and try again.

### Wizard

- **Running Again After a Failure Saved Duplicates:** After a failed run, going *Back* and pressing *Next* to run again
  saved a second mount or job. After a successful run, going *Back* and changing the name left the saved mount or job
  under the old name while *Open Remote* used the new one; *Back* is now unavailable once a run has succeeded.

- **Mounting Another Folder of the Same Remote:** The suggested mount location used only the remote's name, so a second
  folder of the same remote was offered the place the first mount already uses. The name of the folder being mounted is
  now added.

### Startup, Connections, Multiple Windows, and Licensing

- **Connection Errors in the App Log at Every Start:** Each start left several error lines in the app log saying that
  the connection to `127.0.0.1:5582` was refused. They were written while RcloneView was still checking whether rclone
  from the previous session was running, before it started rclone, and did not mean anything had failed. That check now
  writes a single information line, and the remote list is loaded once rclone is up instead of being requested
  beforehand.

- **Connecting to an Rclone That Stopped Responding:** Connecting to an rclone that stopped answering in the middle of a
  reply left a connecting dialog on screen that never closed, and switching to another connection from there hung as
  well.

- **App Lock Exit and Reset at Start-Up:** With App Lock on, *Exit* and *Reset App* on the start-up lock screen did not
  stop the rclone left running by the previous session, and after a reset the next start launched a second one.

- **Restarting Rclone From a Secondary Window:** After *Restart Embedded Rclone*, *Restart Rclone Now*, or *Update
  Rclone* in a secondary window, the main window and other windows stayed on the old rclone and lost their connection
  when its port changed.

- **Settings Reverted Between Windows (Windows):** With more than one window open, a setting saved in one window was not
  seen by the others, and was put back when another window saved its own settings.

- **A Secondary Window Lost Contact With the Main Window:** After one lost reply, every later request from a secondary
  window to the main window failed until that window was closed.

- **Notifications Replaced Earlier Ones (Windows):** After RcloneView was restarted, or with more than one window open,
  a new notification could silently replace an earlier one in the notification center.

- **License Registration on Windows Server:** On computers whose list of trusted certificates lacks Amazon's root
  certificate, such as some Windows Server installations, license registration failed with a certificate error, and so
  did email notifications sent through RcloneView. The certificate is now built into the app for these connections only,
  without turning off certificate checks.

- **License Registration Error Messages:** A failure answered by the license server itself after the fallback request
  method — an invalid key, for example — or a temporary outage of the server still suggested a proxy problem. The text
  copied with *Copy details* now includes the actual reason, such as a certificate error. The message shown when the
  license is accepted but cannot be saved on this computer is now translated and no longer speaks of a Windows user on
  every platform.

- **Trial Messages:** When the trial ended while its reminder was on screen, the *trial ended* message appeared once
  more after it was closed, and someone who had just registered a license could be shown *PLUS Trial Ended*.

### Language and Interface

- **White Dialogs in Dark Mode:** The *Synology NAS Detected* window and the title bar of the *RcloneView Mobile* window
  showed white text on a white background in dark mode.

- **Long Names in Trees:** Long folder names in the explorer's folder tree, and long rule names in the job and Compare
  filter trees, were cut off without "…", and a filter rule's remove button could be pushed out of view.

### Packaging and Updates

- **The AppImage Quit at Start on Recent Distributions (Linux):** On recent distributions such as openSUSE Tumbleweed
  and Slowroll, the AppImage quit right after starting, in both Wayland and X11 sessions, because it carried an older
  copy of a system graphics library. It now uses the one from your system.

- **The AppImage and a Long PATH (Linux):** The AppImage could crash or hang at start when `PATH` was 4096 characters or
  longer or contained an empty entry.

- **Saving Mounts Without xdg-user-dirs (Linux):** On systems without `xdg-user-dirs`, the database could not be opened,
  so saving mount settings failed. The app's own data folder is now used.

- **The Terminal Tab Broke the App's Signature (macOS):** Opening the terminal tab for the first time added a file
  inside the app bundle, after which the app no longer passed macOS's signature check. That file is now created in the
  app's support folder instead.

- **A Silent Install Could Be Rolled Back (Windows):** A silent install could end with exit code 5 and leave the earlier
  version in place when a Windows service, such as the Program Compatibility Assistant, was reading the app's files and
  could not be closed. The installer also closed any other program that had a file of the install folder open. It now
  closes only RcloneView and its bundled rclone, waits until they have ended before replacing files, and leaves other
  copies of rclone running. An interactive install asks before closing them and does not install if you cancel.
