# RcloneView 1.7 – 发行说明

**发布日期：** 2026 年 11 月<br/>
**支持平台：** Windows、macOS、Linux

RcloneView 1.7 让批处理作业结束测试阶段，并新增了远程的导入与导出功能，还可以撤销最近的一次导入。多项过去被 rclone 悄悄忽略的设置现在会按其说明生效——作业的重试次数、同步的删除时机、单字母标志和本地磁盘相关的自定义标志，以及批处理 Check 步骤和空文件夹相关步骤的选项——因此请在升级前阅读第一部分。本版本还允许您直接从作业的 *试运行* 预览中运行该作业，把挂载管理器重新设计为能够显示挂载为何无法工作的表格，重建了挂载窗口，使其包含所有 VFS 选项和 *媒体播放* 类型，为同步新增了 *检测已重命名的文件* 选项，在传输标签页中显示开始和完成时间，并默认在文件浏览器中隐藏系统文件。上传到 Google Drive 现在会在达到每日上限时停止，而不是连续几天反复重试；在卸载时卡住的 macOS 挂载不再拖住应用；非常大的预览也不再让应用卡死。除此之外，本版本还修复了传输、挂载、文件浏览器、多窗口、许可证以及 Linux 软件包方面的一长串问题。

## 升级前请务必阅读

- **批处理作业现在需要 PLUS，并提供 7 天试用。**
  批处理作业已结束测试阶段，现在成为 PLUS 的一部分。在免费许可证下，添加、打开、编辑、复制、预览和运行批处理现在都会要求 PLUS；此前只有为批处理设置计划才需要。在免费许可证下，从此版本首次运行起，批处理作业会在这台计算机上开放 7 天。试用结束时您的批处理不会被删除：它们会以锁定状态保留在作业管理器中，注册 PLUS 许可证后即可重新打开。

- **导入和导出作业与远程需要 PLUS，并提供 7 天试用。**
  作业管理器中的作业 *导入* 和 *导出* 此前是免费的，现在成为 PLUS 的一部分，远程管理器中新增的远程导入和导出也是如此。在免费许可证下，从此版本首次运行起，其中每一项都会在这台计算机上开放 7 天。*撤销最近的导入* 和 *我的远程保存在哪里?* 在所有许可证下都可以使用。

- **同步和复制作业现在会在失败后重试。**
  作业的 *操作失败时重试的最大次数* 设置（默认为 3）以及其自定义标志中的 `--retries` / `--retries-sleep` 从未起过任何作用：rclone 只有在从命令行运行时才会读取它们，因此每个作业都恰好只运行一次。RcloneView 现在会自行重新运行失败的同步或复制作业，规则与 rclone 命令行相同：只有当 rclone 认为这些错误值得重试且其中没有致命错误时才会重试，总尝试次数最多为该数值，并在两次尝试之间等待 `--retries-sleep`。被取消的运行，或因某个远程的登录被拒绝而停止的运行，不会被重试。历史记录、通知和电子邮件只会在最后一次尝试之后报告一次该运行。<br/>
  **这会改变现有作业的行为。** 失败的作业现在需要更长时间才会报告失败，因为默认情况下它会尝试三次；而因暂时性问题失败的运行现在可能会完成。若要让作业只尝试一次，请将该值设为 1。Bisync 作业不受影响。

- **上传到 Google Drive 现在会在达到每日上传上限时停止。**
  Google Drive 每个账户每天大约接受 750 GB 的上传。rclone 过去把这个上限当作普通的速率限制并不断重试，因此一个大型作业可能连续几天保持“运行中”却没有上传任何内容，最后也只显示一个笼统的错误。RcloneView 捆绑的 rclone 现在一旦达到上限就会停止，触及上限的作业会以一条解释该上限的消息结束。请在上限重置后（通常在 24 小时内）再次运行同一个作业：已经复制的文件会被跳过。<br/>
  **这会改变长时间运行的 Google Drive 作业的行为：** 它们现在会在达到上限时以错误结束，而不是等待上限解除。

- **文件浏览器现在会隐藏系统文件，并在复制时将其排除。**
  *设置 → 界面与通知* 中的新设置 *隐藏系统文件* 默认开启。它会在文件浏览器中隐藏 `$RECYCLE.BIN`、`System Volume Information`、`desktop.ini`、`Thumbs.db`、`pagefile.sys`、`hiberfil.sys`、`swapfile.sys`、`.DS_Store`、`.Spotlight-V100`、`.Trashes` 和 `.fseventsd`，并在您于文件浏览器中复制粘贴、拖放、上传或下载时将它们排除在外。作业、比较、移动和重命名不受影响。如果您在文件浏览器中复制整个驱动器，并且需要在目标位置保留这些文件，请关闭该设置。作业过滤器也新增了一个 *系统文件* 分组，默认关闭，用于在作业中排除同样的文件。

- **原本不起作用的自定义标志和批处理选项现在会生效。**
  以下内容过去以 rclone 会丢弃的形式发送给 rclone，因此没有任何效果。它们现在会生效，这会改变使用它们的作业和批处理的行为：
  - 写在自定义标志中、或作为批处理步骤删除时机选项标签的 `--delete-before` 和 `--delete-during`：同步过去总是在传输之后才删除。同时带有 `--delete-before`、`--delete-during` 和 `--delete-after` 中多个标志的作业或步骤现在会拒绝运行，与 rclone 本身的行为一致，并且批处理步骤只允许选择其中一个选项标签。
  - `-c`、`-u` 和 `-M` 等单字母标志过去会在没有任何警告的情况下被丢弃，而跟在不带值的标志之后的单字母标志会被当作该标志的值读取，因此两者都会丢失。现在它们会被展开为对应的长名称；rclone 中不存在的单字母标志会被排除，并显示警告。
  - `--copy-links`（`-L`）、`--skip-links`、`--one-file-system`（`-x`）和 `--skip-specials` 现在会作用于作业的本地源或本地目标；在云端一侧它们不起作用，警告中也会如此说明。使用 `--copy-links` 时，符号链接所指向的文件现在会被复制。
  - `--metadata-include`、`--metadata-exclude`、`--metadata-filter`，以及它们的 `-from` 形式。
  - 批处理 *Check* 步骤的 `--one-way`、`--download`、`--size-only` 和 `--fast-list` 选项标签，以及它的 *附加标志*。

  `--error-on-no-transfer` 和 `--progress` 等 rclone 只从命令行读取的标志，现在会显示警告，说明它们不起作用。请先用 *试运行* 运行一次受影响的作业和批处理，再让它们按计划运行。

- **批处理的空文件夹选项标签现在决定如何处理空文件夹。**
  批处理步骤上的 `--create-empty-src-dirs` 和 `--delete-empty-src-dirs` 选项标签无论开关都不起作用：*Copy Folder* 和 *Sync* 步骤总是在目标位置重新创建空的源文件夹，而 *Move* 步骤除此之外还总会删除它清空的源文件夹。现在每个步骤只有在对应选项标签开启时才会这样做，您已经保存的批处理也是如此。<br/>
  **这会改变现有批处理的行为。** 如果您依赖空文件夹被复制，或依赖 Move 步骤清理它清空的文件夹，请在这些步骤中开启该选项标签。*Rename* 步骤总是移动整个文件夹，其 `--delete-empty-src-dirs` 选项标签已被移除。

- **带有 `--rmdirs` 的批处理 Delete 步骤现在会删除空文件夹。**
  *Delete* 步骤上的 `--rmdirs` 在批处理运行时被忽略；只有预览会显示这些文件夹被删除。现在该步骤在删除文件之后，还会删除其路径下留下的空文件夹，但保留步骤本身的文件夹。该步骤的包含和排除规则同样适用于此；仍含有文件的文件夹——例如含有被 `--min-age` 保留的较新文件——不会被处理。*清理历史* 模板使用了此选项。如果您希望 Delete 步骤之后空文件夹仍然保留，请从该步骤中移除 `--rmdirs`。

- **过去会通过的批处理步骤现在可能失败。**
  *Check* 步骤过去只统计某一侧缺失的文件。内容不同的文件，以及根本无法运行的检查，现在都会让该步骤失败，因此由该步骤的 *错误策略* 决定接下来会发生什么（参见下方的“数据丢失与安全”）。该步骤还新增了输出 `differ` 和 `error_files`。如果某个步骤使用了先前某个未产生输出的步骤的输出——例如在步骤 1 失败并被跳过后使用 `{{step1.differ}}`——它过去会按原文使用该文本运行，从而创建一个以此为名的文件夹；现在它会以 *Not run* 失败并给出原因。如果某个批处理需要在 Check 步骤之后继续执行，请检查该步骤的错误策略。

- **更新后请不要回退到 1.6。**
  本次更新再次更改了数据库格式，以便记录每次传输的完成时间、每个挂载最近一次失败的时间，以及每个挂载的类型和 VFS 设置。如果之后由更早的版本打开该数据库，它会将其删除并从一个空数据库开始：您的作业、批处理、作业历史记录、已保存的挂载和过滤预设都会丢失。远程和设置不受影响。如果您可能需要回退，请在更新前，从设置中显示的 *数据库文件夹* 里保留一份 `rclone_view.db` 的副本。

## 数据丢失与安全

- **批处理 Check 步骤在文件不同时仍然通过：**
  *Check* 步骤把内容不同的文件视为一致，并把失败的检查——远程错误或超时——视为没有发现差异。因此，在删除或移动源之前先检查副本的批处理，可能会继续删除那些副本不一致或从未被检查过的源文件。现在这两种情况都会让该步骤失败。如果您有在 *Delete*、*Purge* 或 *Move* 步骤之前运行 Check 步骤的批处理，请确认目标位置保存着从源位置删除的内容的完整副本。

- **残留的拖动操作可能在下一次点击时复制或移动文件夹：**
  点击时鼠标稍有移动就会开始拖动。当另一个窗口——浏览器中服务商的登录页面、次要窗口、系统对话框——在松开按钮之前抢走了鼠标时，拖动会一直保持，下一次点击（往往是在另一个面板中）就会把它放到那里。这会在没有拖动任何东西的情况下，复制或移动第一个面板中打开的文件夹。这种情况曾在登录服务商、输入许可证密钥、编辑远程，以及添加 S3、B2 或 Mega 远程之后出现。现在以这种方式被中断的拖动会被忽略。如果在执行上述操作之后，传输标签页中出现了不是您启动的传输，请检查这两个文件夹。

- **改为 Rename 的批处理步骤可能只移动部分文件夹：**
  更改步骤的操作时，旧操作的过滤和传输设置值会被隐藏地保留下来，连同它的所有选项标签。一个带有 *最小时间* 过滤条件的 *Move* 步骤被改为 *Rename* 后仍保留该过滤条件，因此重命名只会把匹配的文件移到新名称下，其余文件则留在旧文件夹中。现在更改操作时只会保留新操作提供的选项，并且 Rename 步骤永远不会应用过滤条件，已保存的批处理也是如此。如果您有一个原本是其他操作的 Rename 步骤，请检查旧名称下是否有遗留内容。

## 亮点功能

- **批处理作业结束测试阶段：**
  Beta 标签已被移除，批处理新增了以下功能：*仅重试失败的步骤*——运行失败后，运行窗口会从失败的步骤继续，并传递已完成步骤的输出。失败的运行也可以从批处理的历史记录中重试：已完成的步骤会被跳过，后续步骤需要其输出的较早步骤会重新运行，并且在开始任何操作之前会显示步骤列表。当这次重试本身又被重试时，在之前的运行中已完成的步骤不会重复执行。*在后台运行*——批处理运行期间，运行窗口不再阻挡应用的其余部分。用 *在后台运行* 关闭该窗口，在传输标签页中跟踪批处理，窗口底部的消息会在其完成或失败时告诉您。对已在运行的批处理点击 *运行*，会重新打开它的窗口，而不是启动第二次运行；同一批处理的手动运行与计划运行也不再重叠。*仅更新目标中已有的文件*——Copy 步骤的新选项，只复制目标位置已经存在的文件，因此您尚未下载的文件会留在云端。新的 *按需文件（离线缓存同步）* 模板使用它来让本地离线文件夹与云端文件夹保持同步。

- **导入和导出远程（PLUS）：**
  远程管理器新增了一个用于备份和恢复远程的菜单。*从文件导入远程…* 会读取 rclone 配置文件，并显示哪些远程是新的、哪些已在您的列表中且没有变化、哪些名称相同但设置不同；由您选择要添加哪些。对于已被占用的名称，可选择 *保留我的*（默认）、*使用导入的* 或 *保留两者*——后者会以 `name-2` 这样的空闲名称导入——而 *查看差异* 会列出不同的设置，并隐藏密码和令牌。使用配置密码加密的文件会被拒绝，并附有说明。*将远程导出到文件…* 会保存您的远程，并可选择不包含密码和令牌，从而使该文件可以安全地分享。*撤销最近的导入* 会恢复被某次导入更改的远程：每次导入之前，RcloneView 都会把即将改动的远程保存一份副本，存放在应用的安全存储中，而不是普通文件中。*我的远程保存在哪里?* 会显示配置文件的位置并复制其路径。在连接到并非由 RcloneView 启动的 rclone 时，导入和撤销不可用。如果您自己的 rclone 配置使用密码加密，导入和导出仍然可以使用，并且配置在原处保持加密状态。

- **卸载时卡住的挂载不再拖住应用（macOS）：**
  在 macOS 上，rclone 可能会在卸载挂载时卡住，一直等待一个永远不会结束的系统卸载命令。此时卸载需要 30 秒并以 *卸载失败* 告终，*全部卸载* 大约需要一分钟，列表仍把该挂载显示为已挂载，而退出应用后 rclone 和那个命令还会在后台继续运行。现在卸载会在大约 12 秒后改用系统自身的卸载方式，并立即更新列表；*全部卸载* 不再反复询问卡住的 rclone，挂载管理器也会在处理期间显示进度。退出时，卡住的 rclone 及其启动的卸载命令会被停止——只停止这些进程，并按进程 id 选定。<br/>
  在所有平台上，当 rclone 尚未完成先前的挂载请求时，每个新挂载都会排在它后面等待。应用过去会提示挂载会“在准备就绪后”出现，并在您每次重试时再发送一个请求。现在它会说明 rclone 正忙于另一个挂载，在 rclone 再次响应之前停止发送新的挂载请求，并提供 *重启内嵌 rclone*——同时会先告诉您重启将停止多少个已挂载的驱动器和正在运行的传输。

- **大型预览不再让应用卡死：**
  列出数十万行的试运行——例如整个主文件夹——会让应用卡死。大型预览不再如此：向导最多列出 500 行，但其合计仍会统计全部内容；批处理的详细日志最多保留 5,000 行；错误对话框最多显示 100 行错误。*取消* 现在会立即停止正在运行的作业、向导或批处理预览；持续产生输出的长时间预览会运行到结束；只有在 rclone 五分钟内没有发送任何内容时，预览才会放弃。包含 `{` 或 `}` 的路径不再破坏预览行。另外还修复了：在连接管理器中连接、测试连接或检查 rclone 更新后，加载遮罩可能一直留在屏幕上，挡住所有点击；以及远程管理器在打开期间反复向每个远程请求其详细信息。

## 新增功能与改进

- **直接从试运行开始运行：**
  当作业的 *试运行* 结束时，预览现在会在 *取消* 旁边提供 *运行*。*运行* 会启动同一个作业——使用该作业自身的过滤条件和选项，与预览所见完全一致——效果与 *运行* 按钮相同：如果该作业已在运行，会在重新启动之前先询问您。在一次性的同步/复制对话框中，预览使用表单的当前内容而不保存它，并且作业启动后对话框会关闭。在您添加或编辑作业时，预览仍以 *确定* 结束，因为这些窗口是以 *保存* 结束的。

- **重新设计的挂载管理器：**
  挂载管理器现在以表格列出您的挂载，包含 *状态*、*源*、*挂载点*、*方式* 和 *自动* 列，以及一行摘要，例如 *共 5 个 · 已挂载 3 · 需处理 1*。需要处理的挂载排在最前面——先是 *错误*，然后是 *已断开*，然后是正在处理中的挂载，最后是 *已挂载* 和 *未挂载*——您还可以点击列标题，按状态、源或挂载点排序。*错误*——当挂载失败时，其所在行会显示 rclone 给出的原因和失败时间，按钮也会变为 *重新挂载*。应用启动时失败的自动挂载现在也会以同样的方式记录；此前它只被写入日志。*已断开*——开启了 *自动挂载* 但未挂载的挂载（例如在 rclone 重启之后）会被如此标记，同样提供 *重新挂载*。您自己卸载的挂载则显示为 *未挂载*，直到应用重启。每行的 ⋯ 菜单提供 *打开文件夹*、*复制路径*、*编辑*、*复制* 和 *删除*。*复制* 会以相同的设置和空的挂载点打开新挂载窗口。当挂载处于已挂载状态或仍在挂载或卸载中时，*编辑* 和 *删除* 不可用，菜单会提示先将其卸载。挂载管理器不再在每次成功挂载、卸载或删除后显示消息；失败仍会报告。

- **重新设计的挂载窗口：**
  新建或编辑挂载的窗口现在一开始提供两种类型供选择：*普通文件*，用于打开和保存文档、照片等文件；以及 *媒体播放*，它会填入缓存和预读的值，让 Plex、Jellyfin 和视频播放器能够流畅地读取视频而不卡顿，并以只读方式挂载。它的最大缓存大小会根据缓存所在驱动器的可用空间计算。与该类型所填值不同、由您修改过的值会被标记出来，挂载管理器会为媒体挂载加上 *媒体播放* 标签。设置在左侧分组——*基本*、*缓存*、*播放*、*文件夹列表*、*写入*、*权限* 和 *其他*——并且每个 rclone VFS 选项以及 `--attr-timeout` 现在都有自己的字段。空字段会以灰色显示 rclone 的当前值，并且会按照 rclone 的方式检查输入的值。当同一选项也出现在自定义标志中时，该字段会显示 *已被自定义标志覆盖*，并使用自定义标志中的值。在 *挂载位置* 下，窗口会显示挂载实际出现的位置，在 Windows 上还会显示文件资源管理器对该驱动器的称呼。现在远程路径也可以使用 *浏览*，在 macOS 和 Linux 上挂载位置同样可以使用。*刷新新文件*（关闭，或从每分钟一次到每小时一次）让挂载无需等待其文件夹缓存过期，就能显示远程上新添加的文件——这对不报告变更的远程（例如 SFTP 或 WebDAV）很有用。如果刷新持续失败，或另一个挂载使用了相同的源，挂载管理器中该挂载所在的行会予以说明。对于 *媒体播放*，并行读取数（`--vfs-read-chunk-streams`）取决于远程的类型：PikPak、Proton Drive 和 Filen 为 8，因为它们的单个连接速度太慢，无法流畅播放；其他远程为 0，因为这样打开和定位更快，占用的内存也少得多。Crypt 或其他包装型远程会按其所包装的远程来判断，并且当您选择另一个远程时，该值会随之变化，除非您已经修改过它。当并行读取数设置得过高、会让应用的 rclone 占用多得多的内存时，窗口会发出警告。

- **检测已重命名的文件：**
  单向同步作业新增了 *检测已重命名的文件* 选项（`--track-renames`），批处理 Sync 步骤也以选项标签的形式提供该选项：在源中被重命名或移动的文件会在目标位置被移动，而不是重新上传。当两侧没有共同的哈希时（例如 Crypt 或 SMB），会按名称、大小和修改时间匹配文件。当该选项与 rclone 会忽略它的复制或移动组合使用，或与 rclone 会拒绝的 `--delete-before` 组合使用时，会显示警告。

- **传输标签页中的开始和完成时间：**
  传输标签页新增了 *开始于* 和 *完成于* 列，完整日期显示在工具提示中。完成时间会被保存，因此应用重启后，过去的传输仍会显示完成时间；此次更新之前记录的传输没有完成时间。正在等待或仍在传输中的文件不显示完成时间。

- **在传输标签页中显示重试前的等待：**
  当作业在等待重试时，该次运行的最后一行会显示倒计时的 *30 秒后重试*，并带有一个 ✕，可取消整个运行，从而不再开始后续尝试。

- **向导中更清晰的连接错误：**
  对于 WebDAV 和 SFTP，向导的 *验证* 步骤现在会指出问题所在——例如 *登录失败*、*访问被拒绝*、*未找到 WebDAV 文件夹*、*无法连接到服务器*、*未找到服务器*、*安全连接失败* 或 *服务器身份已更改*——并说明需要检查什么，rclone 的原始消息则位于 *显示详情* 之下。完全无法连接到服务器的情况现在会在 *连接* 步骤显示，而不是在 *认证* 步骤；在 Windows 上，被拒绝或超时的连接也会被识别为此类情况。

- **从挂载或作业处理登录失败：**
  从 1.6 开始，登录被拒绝的远程在您点击 *重试* 之前不会再被连接，但这个按钮只在文件浏览器中提供。过去从挂载管理器或新挂载窗口挂载这样的远程时，会把旧的 rclone 错误当作刚刚发生的一样显示；从窗口运行作业时则只显示一行消息。现在两者都会说明 RcloneView 这次没有进行连接，给出先前的原因，并提供 *编辑远程* 和 *重试*；登录成功后，挂载或作业会继续进行。远程管理器中的 *登录失败* 徽章也会打开同一个窗口。

- **以 Google Photos 作为源：**
  Google Photos 只允许 RcloneView 读取使用该远程自身客户端 ID 上传的照片，因此复制由 Google Photos 应用或网站填充的图库不会传输任何内容。现在当选择 Google Photos 远程作为源时，作业对话框、向导和批处理编辑器会对此加以说明，并附有用于复制整个图库的 Google Takeout 链接。创建 Google Photos 远程时显示的提示也按同样的方式重写，不再要求您运行 rclone 命令。

- **建议为 Google Drive 使用您自己的客户端 ID：**
  未设置 `client_id` 的 Google Drive 远程会使用 rclone 的共享客户端 ID 登录，其请求限额由许多用户共用，因此可能速度很慢或因 403 错误而失败。当 `client_id` 字段为空时，新建远程和编辑远程现在会对此加以说明，并附有 *如何创建自己的客户端 ID* 的链接；没有该字段的向导会说明之后可以通过 *编辑远程* 添加。远程仍然可以在没有客户端 ID 的情况下保存，使用服务账号的远程不受影响。对于这类远程的 *媒体播放* 挂载，挂载窗口也会显示同样的建议，通过 Crypt 或其他包装型远程挂载时也是如此。

- **重试已取消的传输：**
  您在文件浏览器中取消的复制、移动、上传或下载现在也有 *重试* 按钮，与失败的传输一样。其工具提示会说明已复制的文件会被跳过，而正在传输的文件会从头开始。仍在检查文件时被取消的传输现在会显示为 *Canceled*，而不是 *No Changes* 或 *Success*。

- **传输组保持您离开时的状态：**
  展开的传输组不再因您更改过滤条件或另一个传输完成而折叠，新的传输和过去的传输现在也以相同的方式展开。新设置 *折叠显示传输组* 只显示组所在的行；它默认关闭。

- **文件浏览器中的远程卡片：**
  文件浏览器面板中的远程卡片现在在 *打开* 旁边新增了一个用于打开编辑远程的 *编辑* 按钮，并显示与远程管理器相同的存储图表。图表会随卡片放大，*可用* 以绿色显示，放不进圆环的百分比会被省略；图例仍会列出所有数值。过长的远程名称和图例条目会以“…”缩短，而不是在单词中间换行。

- **查找 rclone 日志：**
  *设置 → 内部 Rclone* 中的 *内部 Rclone 日志文件夹* 旁边新增了 *打开日志文件夹* 按钮。它会打开该文件夹并选中日志文件（在 Linux 上只打开文件夹），或者提示该文件夹尚不存在。在 Windows 上，默认日志文件夹现在是您实际的文档文件夹——即文件资源管理器所显示的那个，包括文档文件夹已被移到 OneDrive 的情况——而不再总是 `%USERPROFILE%\Documents`，过去日志在那里无法找到。您自己设置的日志文件夹不会被更改，应用自身的日志仍保留在其原先的默认文件夹中。

- **兼容 DNS 模式（macOS）：**
  在开启 iCloud Private Relay 且远程使用普通 HTTP（例如 Mega）时，macOS 上的 rclone 可能会失去启动新任务的能力，因此挂载和预览永远无法完成。RcloneView 现在会检测并解释这种情况，并提供一个按钮，以新的 *兼容 DNS 模式*（*设置 → 内部 Rclone*，默认关闭）重启 rclone。在该模式下，以 `.local` 结尾的名称以及只有您的 VPN 才知道的名称将无法解析，当此类名称解析失败时，应用会指出这一点。

- **用 ⌘, 打开设置（macOS）：**
  当没有打开任何对话框或菜单时，⌘, 现在会像其他 Mac 应用一样打开常规设置。

- **启动问题说明：**
  当捆绑的 rclone 缺失时，启动消息现在会显示 *未找到 rclone 可执行文件*，并建议重新安装或在杀毒软件中允许 RcloneView，而不是笼统的 *无有效连接*。在 Windows 上，窗口打开之前发生的错误现在会显示在消息框中，并附有日志文件的位置和可以尝试的操作，而不是留下一个隐藏的进程；当之前启动的 RcloneView 仍在运行但无响应时，再次启动 RcloneView 现在会对此加以说明并解释如何结束它，而不是毫无反应。

- **RcloneView Mobile 1.1 新功能：**
  *RcloneView Mobile* 窗口现在会展示移动应用 1.1 更新新增的内容——流式播放、云端之间的复制与同步，以及照片备份后释放手机空间，这些都属于 Plus——并附有一段可按场景跳转的短视频。窗口中提供 Google Play 和 App Store 的二维码与按钮，*发送远程到手机* 只需扫描一次即可把这台 PC 的远程转移到手机上。更新后该窗口会自动打开一次，即使您曾为之前的公告选择了 *不再显示*；再次选择它会隐藏菜单栏按钮，而 *帮助 → RcloneView Mobile* 仍可打开该窗口。视频会从 rcloneview.com 下载一次，并从临时副本播放；窗口自动打开时，会等到视频准备就绪再显示。没有互联网连接时，窗口会改为显示一张介绍新功能的图片。

## 问题修复

### 作业、批处理与传输

- **在作业运行时再次运行它：** 对正在运行的作业点击 *运行* 并选择 *继续*，会取消正在运行的那次，却从未启动新的一次；被取消的运行还会显示“Job N error”对话框，随后被关闭的却是这个对话框，而不是作业管理器。现在应用会等待旧的运行停止后再重新开始，如果它没有及时停止会予以说明，并将被取消的运行记录为 *Canceled*。

- **关闭试运行错误时关闭了作业管理器：** 关闭试运行的错误对话框时，其下方的作业管理器或同步/复制对话框也会一并关闭。

- **文件夹深度错误自行关闭：** 在开启 *不处理超过此深度的文件夹* 但输入框为空的情况下运行作业，其错误消息会一闪而过并自行关闭，就像作业已经启动了一样。

- **试运行和计划 bisync 期间出现空白 rclone 窗口（Windows）：** 每次试运行都会打开一个标题为 rclone 的空白控制台窗口，关闭该窗口会停止试运行。在 5 秒内完成的 bisync 作业（计划运行通常如此）也会短暂闪现一个空白控制台窗口，即使设置了 `--no-console` 也是如此。

- **短时间的 bisync 运行会运行两次：** 在 5 秒内完成的 bisync 作业——无事可做的计划 bisync 通常如此——会紧接着再运行一次以收集错误详情，即使第一次已经成功。第二次运行是真正的 bisync：在两次之间更改的文件会被传输，却不会显示在进度或历史记录中；开启了 resync 的作业会再次 resync；在 5 秒内被取消的 bisync 会再次启动。现在只有在第一次运行失败时才会进行第二次运行，因此其错误信息仍会显示。

- **多余的逗号让计划每次都运行：** 以逗号结尾的计划字段（例如 `5,`）会在保存作业时被清空，而空值表示“每一”。`1,2,3` 这样列表中间的数字也无法删除；在批处理中，残留的 `1,,3` 会按原样保存，并被调度器拒绝。现在空的部分会被移除（`1,,3` 变为 `1,3`），批处理编辑器会在 *模拟* 或 *保存* 之后显示整理后的值。

- **预览中的每月计划：** 对于每月运行一次的计划，即将运行的列表只显示 3 次运行，而不是 10 次。

- **计划批处理发生重叠：** 运行时间超过其间隔的计划批处理会在完成后立即再次运行，或在其运行期间同时启动第二次运行。现在在运行仍在进行期间经过的计划时间会被跳过。

- **通过 Web 服务器更改的作业：** 通过 Web 服务器的 API 创建、更改或删除作业后，计划在应用重启之前不会更新：新计划不会运行，更改过的计划仍按旧时间运行，已删除的作业仍会继续运行。

- **机器人在什么都没启动时回复“已启动”：** Telegram、Slack 和 Discord 机器人即使在作业因已在运行或某个远程登录失败而没有启动时，也会回复 *已启动作业*。现在它们会说明作业未启动的原因。

- **作业名称重复：** 作业管理器中的 *复制* 可能会给副本取一个已被另一个连接的作业使用的名称，之后保存时会因“Job name already exists”而失败；而 `Job (1)` 的副本会被命名为 `Job (1)
  (3)`。名称仅在开头或结尾的空格上不同的两个作业也都可以被保存。

- **批处理试运行显示“No Changes”：** 批处理 *Delete* 或 *Purge* 步骤的预览列出了将要删除的文件，却仍然显示没有变更；而在同一远程内的 *Move* 的预览则根本不显示任何变更。取消批处理试运行时会显示 *完成 — 无需更改*；现在它会说明有多少个步骤未被检查。

- **已取消的批处理被保存了两次：** 取消批处理运行时，它会被保存到历史记录中两次，一次为已取消，一次为失败。

- **自定义标志中的 `--dscp` 和 `--metadata-set`：** `--dscp` 现在会按照 rclone 的方式读取，即 0 到 63 之间的数字或 `AF21` 这样的名称。过去像 18 这样的数字会设置成另一个值，而名称会因“not a number”被丢弃。通过 `--metadata-set` 给出的键现在会像 rclone 一样以小写形式发送。

- **两个本地文件夹之间的带宽限制（macOS）：** 两个本地文件夹之间的批处理 Copy 或 Sync 步骤会忽略其带宽限制，因为文件是由 macOS 自己复制的。设置了限制后，这些步骤现在会通过 rclone 复制并遵守该限制。

- **已复制的文件显示为“No Changes”：** rclone 1.75 实际上已经复制的小文件，在传输详情中显示为 *No Changes*。

- **上传卡在“Queued”：** 覆盖同名现有文件的上传在整个上传过程中一直停留在 *Queued* 和 0%，而空文件会一直停留在 *Queued*，然后显示 *No Changes*。

- **传输详情中的文件名被截短：** 名称以目标文件夹名称开头的文件会丢失这一部分——`support-sitemap.xml` 显示为 `-sitemap.xml`——并且已传输的空文件显示为 0%。

- **备份副本被列为已传输：** 在设置了备份文件夹、同步到无法在服务器端移动文件的存储时，被移入备份文件夹的文件会被列为已传输，并且作业详情会在没有任何遗漏的情况下提示只显示了部分列表。

- **源列中重复出现文件夹名称：** 失败或已取消的文件夹传输会把其源显示为 `…/big/big/big`，每次刷新都会再添加一次名称。

- **较早的传输历史记录消失：** rclone 每次启动时都会从 1 重新给作业编号，使用相同编号的新运行会删除较早运行的传输记录。当一个并非由 RcloneView 启动的 rclone 在同一地址上重启时，重启前后的运行也会混在一起。

- **最大化传输面板：** 还原已最大化的传输面板时，两个文件浏览器面板都会切回各自的第一个标签页，因此之后启动的同步会使用这些标签页，传输列表也会跳回顶部。

### 挂载

- **已挂载的驱动器被标记为已卸载（Windows）：** 当 rclone 正忙于某个挂载而没有响应时，仍处于挂载状态的驱动器会被记录为已卸载。连接到另一台机器上的 rclone 时也会发生这种情况。

- **从托盘卸载失败：** 从托盘菜单卸载失败时不会显示任何内容；现在会显示系统通知。*全部卸载* 不再在 rclone 只是响应缓慢时显示错误对话框，并会检查驱动器是否确实已经消失。

- **失败的挂载留下空文件夹：** 挂载失败时，RcloneView 为其创建的空挂载点文件夹会被留下。现在它会被移除；之前就已存在的文件夹不会被处理。

- **有名称的本地远程上的绝对路径（macOS 和 Linux）：** 从有名称的本地远程挂载 `/home/me/x` 这样的路径时，实际挂载的是您主文件夹内的 `/home/me/x`——一个空文件夹，却显示为已挂载。RcloneView 现在会检查哪个文件夹存在，如果都不存在，则以 *未找到文件夹* 失败。

- **更多已挂载的本地远程被列为“已配置”（Windows）：** 名称恰好为 `local` 的本地远程、本地驱动器根目录或相对路径的挂载，以及 `loc:C:` 这样的 alias，在挂载后仍被列为 *已配置*。

- **挂载文件夹名称已被占用（Windows）：** 在同一位置再次挂载同一个远程时，会建议相同的文件夹名称，并以笼统的“already exists”消息失败。挂载管理器现在会说明该名称在何处已被占用，并提供一个空闲的名称，例如远程名称后接正在挂载的文件夹名称。

- **保存了空的挂载点（macOS 和 Linux）：** 挂载可能在挂载点文件夹名称为空的情况下被保存，这可能导致其挂载点变为 `/`。新挂载和编辑挂载窗口现在会在保存前要求输入文件夹名称。

### 文件浏览器、比较与过滤

- **无法读取的本地文件夹看起来是空的：** 您的账户无法读取的本地文件夹会显示为空文件夹。现在它会显示为无法加载的文件夹，并附有关于磁盘访问和权限的建议，通过 alias 或 Crypt 远程访问时也是如此。

- **文件夹选择器只显示“/”：** 当远程的顶层文件夹无法读取时——服务器已关闭或拒绝连接——*选择远程和文件夹* 以及挂载和批处理步骤的文件夹选择器会只显示一个 `/`，就像一个空的远程。现在它们会显示 *无法加载此文件夹* 并提供 *重试*。

- **文件夹选择器选中了上一个远程的文件夹：** 在上一个远程加载完成之前于 *选择远程和文件夹* 中切换远程，可能会让列表填满上一个远程的文件夹，并选中其中一个。

- **在本地磁盘标签页中输入路径（Windows）：** 在路径栏中输入另一个驱动器上的文件夹并跳转过去后，比较、同步/复制和作业管理器使用的是带有该路径的标签页的第一个驱动器，并因“directory not found”而失败。

- **新建文件夹在什么都没创建时报告成功：** 只要 rclone 接受了请求，日志就会显示“completed successfully”，即使随后创建文件夹失败。在无法保留空文件夹的存储上，例如 B2 和兼容 S3 的存储，文件夹从未被创建，而所有地方都显示已创建。现在日志会记录实际结果，在这种情况下该行会显示 *失败*，并说明放入文件后文件夹才会出现。

- **重命名重复项：** 重命名名称重复的文件时，没有使用您的 rclone 配置文件和全局标志，即使失败也会报告为已完成。现在会显示失败。

- **重命名或新建文件夹后的文件夹树：** 重命名或创建文件夹后，文件夹树可能显示旧的内容并折叠已展开的文件夹；当重命名未能开始时，文件列表可能一直停留在加载指示器上。

- **比较列出了被过滤掉的文件夹和空文件夹：** 比较结果仍会显示其中所有文件都被过滤条件排除的文件夹，以及每个本身不含文件的中间文件夹所对应的行。

- **比较中的复制始终无法完成：** 从比较视图复制时如果无法连接 rclone，各行永远不会完成，窗口也一直处于传输状态。现在在连续三次状态检查失败后，受影响的行会被标记为失败，复制会继续进行。

- **在比较中选择 alias 远程的文件夹：** 文件夹选择器为 alias 远程打开的是一棵空的树，并且在那里选择的文件夹会以 alias 所指向的远程的名称返回。

- **过滤中的“Others”一直保持勾选：** 在作业或比较的过滤树中删除 *Others* 下唯一的规则后，*Others* 仍保持勾选，而其下没有任何内容。

### 远程与登录

- **保存远程会中断其他远程：** 添加、编辑或删除远程时会清除 rclone 对所有远程的缓存，这可能会中断其他远程上的传输和挂载。现在只有当另一个远程（例如 Crypt 或 Union 远程）或 alias 依赖于发生更改的那个远程时，才会清除整个缓存。

- **遗漏了对配置文件的更改：** 如果应用启动时 `rclone.conf` 尚不存在、该文件被删除后又重新创建，或在 *更新 Rclone* 之后，RcloneView 就不再察觉在应用之外对该文件所做的更改。在应用自身保存远程期间所做的更改也可能丢失。连接到并非由 RcloneView 启动的 rclone 时，不再比较该文件。

- **登录失败状态在连接之间共享：** 两个 rclone 连接上同名的远程共用同一条登录记录，因此一个连接上的失败会阻塞另一个连接上正常工作的远程，而在一个连接上通过的检查也会被另一个连接信任。现在每个连接都会保存各自的记录。

- **找不到 Oracle Object Storage 私钥：** 当 OCI 配置中的 `key_file` 只是一个文件名或相对路径时，RcloneView 内的 rclone 无法找到该密钥。错误界面现在会解释这一点以及如何修复：写入完整路径，重启内嵌的 rclone，然后重试。

### 向导

- **失败后再次运行会保存重复项：** 运行失败后，点击 *返回* 再点击 *下一步* 重新运行，会保存第二个挂载或作业。运行成功后，点击 *返回* 并更改名称，会让已保存的挂载或作业保留旧名称，而 *打开远程* 却使用新名称；现在一旦运行成功，*返回* 就不再可用。

- **挂载同一远程的另一个文件夹：** 建议的挂载位置只使用远程的名称，因此同一远程的第二个文件夹会被建议使用第一个挂载已占用的位置。现在会加上正在挂载的文件夹的名称。

### 启动、连接、多窗口与许可证

- **每次启动时应用日志中都有连接错误：** 每次启动都会在应用日志中留下几行错误，表示与 `127.0.0.1:5582` 的连接被拒绝。这些错误是在 RcloneView 启动 rclone 之前、仍在检查上一会话的 rclone 是否在运行时写入的，并不意味着有任何操作失败。现在该检查只会写入一行信息，并且远程列表会在 rclone 启动后再加载，而不是提前请求。

- **连接到停止响应的 rclone：** 连接到在回复中途停止应答的 rclone 时，会在屏幕上留下一个永远不会关闭的连接对话框，从那里切换到另一个连接也会卡住。

- **启动时应用锁的退出和重置：** 开启应用锁时，启动时锁定屏幕上的 *退出* 和 *重置应用* 不会停止上一会话遗留运行的 rclone，并且重置后下一次启动会再启动一个 rclone。

- **从次要窗口重启 rclone：** 在次要窗口中执行 *重启内嵌 rclone*、*立即重启Rclone* 或 *更新 Rclone* 后，主窗口和其他窗口仍停留在旧的 rclone 上，并在其端口变化时失去连接。

- **窗口之间的设置被还原（Windows）：** 打开多个窗口时，在一个窗口中保存的设置不会被其他窗口看到，并会在另一个窗口保存自己的设置时被还原。

- **次要窗口与主窗口失去联系：** 丢失一次回复后，次要窗口之后发往主窗口的每个请求都会失败，直到该窗口被关闭。

- **通知替换了之前的通知（Windows）：** RcloneView 重启后，或打开多个窗口时，新的通知可能会在通知中心悄悄替换之前的通知。

- **在 Windows Server 上注册许可证：** 在受信任证书列表中缺少 Amazon 根证书的计算机上（例如某些 Windows Server 安装），许可证注册会因证书错误而失败，通过 RcloneView 发送的电子邮件通知也是如此。现在该证书仅针对这些连接内置于应用中，并且不会关闭证书检查。

- **许可证注册错误信息：** 在回退请求方法之后由许可证服务器本身应答的失败（例如密钥无效），或服务器的临时中断，仍会提示代理问题。用 *复制详情* 复制的文本现在会包含实际原因，例如证书错误。许可证已被接受但无法保存在这台计算机上时显示的消息现在已经翻译，并且不再在所有平台上都提到 Windows 用户。

- **试用消息：** 当试用在其提醒显示期间结束时，*试用已结束* 消息会在提醒关闭后再出现一次；刚刚注册了许可证的用户也可能看到 *PLUS 试用结束*。

### 语言与界面

- **深色模式下的白色对话框：** 在深色模式下，*Synology NAS Detected* 窗口和 *RcloneView Mobile* 窗口的标题栏会在白色背景上显示白色文字。

- **树中的长名称：** 文件浏览器文件夹树中的长文件夹名称，以及作业和比较过滤树中的长规则名称，会在没有“…”的情况下被截断，过滤规则的删除按钮也可能被挤出视野。

### 打包与更新

- **AppImage 在较新的发行版上启动即退出（Linux）：** 在 openSUSE Tumbleweed 和 Slowroll 等较新的发行版上，AppImage 在 Wayland 和 X11 会话中都会在启动后立即退出，因为它携带了一个较旧的系统图形库副本。现在它会使用您系统中的那个库。

- **AppImage 与过长的 PATH（Linux）：** 当 `PATH` 达到或超过 4096 个字符，或包含空条目时，AppImage 可能会在启动时崩溃或卡住。

- **在没有 xdg-user-dirs 的系统上保存挂载（Linux）：** 在没有 `xdg-user-dirs` 的系统上，数据库无法打开，因此保存挂载设置会失败。现在会使用应用自身的数据文件夹。

- **终端标签页破坏了应用的签名（macOS）：** 首次打开终端标签页时会在应用包内添加一个文件，此后应用便无法通过 macOS 的签名检查。现在该文件改为在应用的支持文件夹中创建。

- **静默安装可能被回滚（Windows）：** 当某个 Windows 服务（例如程序兼容性助手）正在读取应用的文件而无法被关闭时，静默安装可能会以退出代码 5 结束，并保留之前的版本。安装程序还会关闭任何打开了安装文件夹中文件的其他程序。现在它只会关闭 RcloneView 及其捆绑的 rclone，等它们结束后再替换文件，并让其他 rclone 副本继续运行。交互式安装会在关闭它们之前先询问，如果您取消则不会安装。
