# RcloneView 1.6 – 릴리스 노트

**출시일:** 2026년 10월<br/>
**지원 플랫폼:** Windows, macOS, Linux

RcloneView 1.6은 정확성에 초점을 맞춘 릴리스입니다. 파일이 사라질 수 있던 두 가지 경로와 열려 있던 네트워크 포트 하나를 막았고, 작업에 입력한 플래그가 이제 실제로 rclone에 전달되며, 실패한 동기화가 더는 완료된 것처럼 보고되지 않고, RcloneView가 자신이 시작하지 않은 rclone 프로세스를 종료하지 않습니다. 이후 1.6 업데이트에서는 비밀번호가 틀린 리모트가 서버에 이 컴퓨터가 차단될 때까지 계속 로그인을 시도하는 문제와, 예약된 작업이 열려 있는 창마다 한 번씩 실행되는 문제도 해결했습니다. 이와 함께 마운트, 탐색기, 리모트 생성, 마법사, 그리고 세 플랫폼의 패키징 전반에 걸친 많은 문제를 수정했습니다.

## 업그레이드 전에 꼭 읽어 주세요

- **작업의 사용자 정의 플래그에 입력한 필터 플래그가 이제 적용됩니다.**
  작업의 *사용자 정의 플래그* 입력란에 적은 `--include`, `--exclude`, `--filter` 같은 필터 플래그가 작업 실행 전에 버려지고 있었습니다.
  이 플래그는 시험 실행과 bisync 진단에서만 적용되었기 때문에, 미리 보기와 실제 실행의 결과가 서로 다를 수 있었습니다.
  이제 모든 경로에서 플래그가 전달됩니다.<br/>
  **이 변경은 기존 작업의 동작을 바꿉니다.** 사용자 정의 플래그에 필터가 있는 작업은 이제 모든 파일이 아니라
  조건에 맞는 파일만 전송합니다. 삭제가 활성화된 *동기화* 작업이라면 대상에서 삭제되는 파일도 달라집니다.
  사용자 정의 플래그에 필터를 둔 작업이 있다면 모두 검토하시고, 일정에 따라 실행되도록 두기 전에 *시험 실행*으로 한 번 실행해 보세요.

- **비밀번호가 긴 토큰인 리모트는 비밀번호를 한 번 더 입력해야 합니다.**
  리모트를 저장할 때 RcloneView는 전달받은 비밀번호를 인코딩해야 하는지를 rclone이 스스로 판단하도록 맡겨 두었습니다.
  base64처럼 보이는 비밀번호에서는 이 판단이 항상 틀렸고, 그 결과 값이 인코딩되지 않은 채 구성에 기록된 뒤
  연결을 시도할 때마다 뒤섞였습니다. 이렇게 저장된 리모트는 한 번도 인증에 성공하지 못했습니다.
  이제 RcloneView가 비밀번호를 직접 인코딩하므로, 이 버전부터 추가하거나 편집하는 리모트는 올바르게 저장됩니다.<br/>
  **이미 그렇게 저장된 리모트는 업데이트로 복구되지 않습니다.** 영향을 받는 것은 영문자, 숫자, `-`, `_`로만 이루어진
  22자 이상의 비밀번호입니다. 직접 정한 비밀번호가 아니라 API 토큰이나 자동 생성된 앱 비밀번호가 여기에 해당합니다.
  인증 오류로 연결에 계속 실패하던 리모트가 있다면 *리모트 관리자 → 편집*에서 해당 리모트를 열어 비밀번호를 다시
  입력하고 저장하세요. 그 이후로는 정상적으로 연결됩니다.<br/>
  **현재 정상적으로 열리는 Crypt 리모트의 비밀번호는 다시 입력하지 마세요.** 이렇게 저장된 Crypt 리모트는 실패한 적이
  없습니다. 파일이 뒤섞인 값으로 암호화되었고, 그 값으로만 다시 읽을 수 있기 때문입니다. 지금 실제 비밀번호를 입력하면
  리모트가 다른 키로 바뀌어, 이미 들어 있는 파일을 더는 열 수 없게 됩니다. 이런 리모트는 그대로 두세요. 다른 설정을
  편집하는 것은 안전합니다. 이미 비밀번호를 다시 입력했고 파일이 열리지 않게 되었다면, `rclone.conf`에 이전 값을
  되돌려 넣으세요. 그 값은 인코딩 없이 기록된 비밀번호 자체입니다. 이런 리모트를 실제 비밀번호로 옮기려면 먼저 기존
  리모트를 통해 파일을 밖으로 복사한 다음, 리모트를 새로 만드세요.

- **앱 잠금을 켜 두면 앱이 잠금 해제되기 전에는 아무것도 시작되지 않습니다.**
  이제 잠금 화면이 모든 창 콘텐츠보다 먼저 표시되며, rclone, 예약된 작업, 자동 마운트, 웹 서버가 잠금 화면 뒤에서
  시작되지 않고 비밀번호 입력을 기다립니다. 앱 잠금이 켜진 상태에서 로그인할 때 RcloneView가 시작되도록 설정했다면,
  누군가 잠금을 해제하기 전까지 예약된 작업과 자동 마운트가 실행되지 않습니다. 이 컴퓨터가 재시작 후 사람이 없어도 작업이나
  마운트가 실행되는 것에 의존한다면, 앱 잠금을 끄거나 로그인할 때마다 앱 잠금을 해제하세요.

- **로그인이 거부된 리모트에는 더 이상 자동으로 접속하지 않습니다.**
  비밀번호로 로그인하는 리모트(SFTP, FTP, WebDAV, SMB)의 경우, RcloneView가 이제 로그인을 한 번 확인하고 서버가
  거부하면 해당 리모트에 대한 접속을 중단합니다. 자동 마운트, 예약된 작업, 탭 다시 열기가 모두 중단됩니다.
  이 상태는 재시작 후에도 유지됩니다. 이런 리모트를 사용하는 예약된 작업은 실패로 기록되고 평소와 같은 실패 알림이
  전송됩니다. 탐색기에서 *다시 시도*를 누르거나 *원격 편집*에서 수정한 비밀번호를 저장하면 접속이 재개됩니다.<br/>
  **서버가 일정 기간 동안만 로그인을 거부하는 경우** (예: 비밀번호를 변경하는 동안) 해당 리모트의 예약된 작업은 그 이후에도
  누군가 *다시 시도*를 누를 때까지 일시 중지된 상태로 남습니다. 브라우저나 키로 로그인하는 클라우드 스토리지는
  영향을 받지 않습니다.

- **예약된 작업은 이제 메인 창에서만 실행됩니다.**
  일정은 메인 창의 rclone 연결을 따릅니다. 보조 창만 다른 연결로 전환했다면, 그 창이 열려 있는 동안에는 해당 연결의
  예약된 작업이 실행되지 않습니다. 대신 메인 창에서 연결을 선택하세요. 메인 창이 예기치 않게 닫히면 다른 창이 아직 열려
  있더라도 RcloneView를 다시 시작할 때까지 예약된 작업이 중지됩니다.

## 데이터 손실 및 보안

- **일부만 실패한 삭제를 재시도하면 상위 폴더가 통째로 삭제될 수 있었습니다:**
  여러 파일을 한 번에 삭제하다가 일부가 실패한 뒤 *재시도*를 누르면, 실패한 파일만 다시 시도하는 대신 상위 폴더 전체가
  삭제될 수 있었습니다. 이제 재시도는 실패한 항목에만 적용됩니다.

- **`[` `]` `*` `?` `{`가 들어간 파일 이름이 엉뚱한 파일을 삭제할 수 있었습니다:**
  여러 파일을 삭제할 때 경로를 이스케이프하지 않은 채 rclone의 필터 엔진에 넘겼기 때문에, 패턴 문자가 들어간 이름이
  와일드카드로 처리되었습니다. 파일 하나를 삭제해도 다른 폴더의 파일이 일치하여 함께 삭제될 수 있었습니다.
  이제 경로를 필터로 사용하기 전에 이스케이프합니다.

- **이미 있는 이름으로 리모트를 만들면 기존 리모트가 대체되었습니다:**
  rclone은 "생성"을 "생성 또는 업데이트"로 처리하므로, 이미 사용 중인 이름으로 리모트를 만들면 스토리지 유형이 달라도
  기존 리모트의 설정과 자격 증명이 조용히 덮어써졌습니다. 이제 새 리모트 대화상자, 마법사, 마법사의 Crypt 단계에서
  이미 사용 중인 이름을 입력하는 즉시 경고하며 다음 단계로 진행하지 않습니다.

- **창 간 통신 포트가 네트워크에 열려 있었습니다:**
  RcloneView가 자체 창 사이의 통신에 사용하는 포트(13542)가 이 컴퓨터만이 아니라 모든 네트워크 인터페이스에서
  수신 대기 중이었고, 메인 창은 빈 인증 키도 받아들였습니다. 이제 로컬 컴퓨터에만 바인딩되며 유효한 키를 요구합니다.

## 주요 변경 사항

- **RcloneView가 더 이상 다른 rclone 프로세스를 종료하지 않습니다:**
  앱을 종료하거나, rclone을 재시작하거나, *Rclone 업데이트*를 실행하면 이름으로 rclone을 종료했기 때문에, 컴퓨터에서
  실행 중인 다른 모든 rclone도 함께 종료되었습니다. 터미널에서 시작한 `rclone mount`, cron 작업, rclone을 사용하는 다른
  도구가 여기에 해당합니다. 이제 RcloneView는 자신이 시작한 프로세스만 종료합니다.

- **비밀번호가 틀려도 이 컴퓨터가 차단되지 않습니다:**
  비밀번호가 틀린 SFTP 리모트 하나가 NAS가 이 컴퓨터의 IP 주소를 차단할 때까지 수십 번 로그인을 시도할 수 있었습니다.
  rclone은 거부된 로그인을 요청당 최대 열 번 재시도하고, 탭 하나를 열면 여러 요청이 동시에 전송되며, 앱은 실패한 목록
  조회를 세 번 더 재시도했습니다. 탭 하나에 로그인 시도가 약 80번 발생한 셈입니다. 또한 앱은 시작할 때, 탭을 복원할 때,
  자동 마운트와 예약된 작업을 실행할 때 스스로 접속했습니다. 비밀번호로 로그인하는 리모트(SFTP, FTP, WebDAV, SMB)의
  경우 이제 RcloneView가 로그인을 한 번 확인하고 거부되면 중단합니다. 탐색기에는 *로그인 실패*와 함께 *리모트 편집*,
  *다시 시도* 버튼이 표시되며(Crypt나 alias 리모트는 그 아래에 있는 리모트를 가리킵니다), 리모트 관리자에는 여유 공간
  대신 *로그인 실패* 배지가 표시됩니다. *새 리모트*에서 틀린 비밀번호로 추가한 리모트는 저장되지 않습니다. 반복된 실패 후
  서버가 응답하지 않으면, 탐색기가 약 50초 동안 로딩만 표시하는 대신 몇 초 안에 IP가 차단되었을 수 있다고 알려 줍니다.

- **예약된 작업이 열려 있는 창마다 한 번씩 실행되었습니다:**
  RcloneView 창마다 자체 스케줄러가 실행되어, 창이 하나 더 열려 있으면 예약된 모든 작업과 배치가 창마다 같은 시각에
  한 번씩 시작되었습니다. 같은 로컬 폴더에 쓰는 두 사본이 서로의 부분 파일을 삭제하여, 아무것도 복사되지 않은 채
  실행이 끝날 수 있었습니다. 보조 창에서 일정을 변경하거나 삭제해도 메인 창이 이전 일정을 계속 실행했습니다.
  이제 일정은 메인 창에서만 실행되며, 다른 창에서 변경한 내용은 메인 창으로 전달됩니다. 일정이 실행되는 순간에 *실행*을
  누르거나 빠르게 두 번 누르면 같은 작업이 두 번 시작될 수 있었는데, 이제는 한 번만 시작됩니다.

- **업그레이드 이전의 Rclone이 계속 실행되었습니다:**
  이전 버전이 실행해 둔 rclone이 RcloneView 업그레이드 후에도 재사용되어, 그 프로세스를 직접 종료하기 전까지는 새로 번들된
  rclone이 사용되지 않았습니다. 이제 RcloneView는 실행 중인 버전이 다르면 rclone을 재시작합니다. 또한 rclone의 포트를
  우연히 사용하는 다른 프로그램을 rclone으로 오인하지 않으며(그 때문에 앱에 *연결 없음*만 표시되었습니다), 대신 다음
  빈 포트에서 rclone을 시작합니다. rclone을 종료하거나 재시작할 때 앱은 이제 rclone이 스스로 종료되기를 기다립니다.
  이전에는 마운트가 해제되고 VFS 캐시가 정리되기 전에 매번 강제로 종료했습니다.

- **사용자 정의 플래그와 전역 플래그가 실제로 적용됩니다:**
  설정한 플래그가 여러 가지 방식으로 조용히 버려지고 있었고, 그래서 명령줄에서는 동작하던 플래그가 앱에서는 아무
  효과가 없는 것처럼 보였습니다. 이번 릴리스에서 수정한 내용은 다음과 같습니다. 설정의 rclone 전역 플래그가 동기화/복사
  작업에 적용되지 않았습니다. 작업의 사용자 정의 플래그에 넣은 백엔드 플래그와 프로세스 전체 플래그가 무시되었습니다.
  배치 단계 필드(대역폭 제한, Include, 최소/최대 기간, 최소/최대 크기)가 rclone이 버리는 형식으로 전송되었습니다.
  숫자로 쓴 불리언 플래그(`--checksum=1`, 명령줄에서는 유효함) 때문에 요청 전체가 실패하여 작업이 시작되지 않았습니다.
  `--backup-dir`과 `--compare-dest` 플래그를 반복해서 쓰면 거부되었습니다. `--header`, `--header-upload`,
  `--header-download`, `--compare-dest`가 잘못된 형식으로 변환되었습니다. 플래그 파서가 값 안의 따옴표나 공백을
  처리하지 못했습니다. 시험 실행에 사용자 정의 플래그가 전혀 포함되지 않아 미리 보기가 실제 실행과 달랐습니다.
  전역 플래그 입력란에 잘못된 문자가 하나만 있어도 문제가 된 플래그만이 아니라 모든 플래그가 조용히 버려졌습니다.

- **실패한 동기화가 더 이상 "변경 없음"으로 보고되지 않습니다:**
  자격 증명 오류, 연결할 수 없는 리모트, 존재하지 않는 경로처럼 아무것도 전송하기 전에 실패한 동기화가 작업 목록, 기록,
  알림에서 변경 사항 없이 완료된 실행으로 표시되었습니다. 이제 rclone이 작업에 대해 보고하는 오류를 읽으므로 실패는
  실패로 표시됩니다.

- **목록 조회 실패가 더 이상 빈 폴더로 처리되지 않습니다:**
  폴더의 목록을 가져오지 못했을 때 앱의 여러 부분이 단순히 비어 있는 것으로 가정했습니다. 그래서 기존 콘텐츠 위에 마운트가
  만들어질 수 있었고, 마운트 *검증*이 항상 통과했으며, 폴더 트리, 비교, 경로 선택기가 파일이 가득한 폴더를 아무것도 없는
  것처럼 표시할 수 있었습니다. 이제 목록 조회 실패는 실패로 보고되며, 목록 보기에도 빈 폴더처럼 보이는 대신 실패로
  표시됩니다.

- **중단된 로그인이 모든 새 리모트를 막았습니다:**
  로그인을 끝내지 않고 제공업체의 로그인 페이지를 닫으면 rclone의 인증 도우미가 53682 포트를 점유한 채 남았고, 그 뒤로
  브라우저로 로그인하는 리모트를 만드는 모든 시도가 실패했습니다. 앱을 재시작해도 해제되지 않았으며, rclone을 강제
  종료하는 것이 유일한 방법이었습니다. 이제 로그인이 중단되면 도우미가 종료됩니다.

## 신규 기능 및 개선 사항

- **작업별 업로드 동시성:**
  백엔드 업로드 동시성(`upload_concurrency`)을 전역으로만 설정하는 대신 개별 작업에 설정할 수 있게 되었습니다. 따라서
  빠른 리모트를 대상으로 하는 작업이 다른 모든 작업과 하나의 설정을 공유하지 않아도 됩니다.

- **새 리모트가 바로 패널에서 열립니다:**
  리모트를 만들면 직접 찾아서 열 필요 없이 곧바로 탐색기 패널에서 열립니다.

- **탐색기에 여유 공간 표시:**
  여유 공간을 보고할 수 있는 리모트의 경우 이제 파일 탐색기에 리모트의 남은 공간이 표시됩니다.

- **비교 보기에서 더 빠른 복사:**
  비교 보기에서 복사하면 항목마다 rclone 작업을 하나씩 시작했고, `--transfers` 설정과 관계없이 네 개씩 실행했습니다.
  이제 항목을 리모트와 상위 폴더별로 하나의 동기화/복사로 묶으며, `--transfers` 설정이 지켜집니다.

- **"구성 파일이 변경됨" 팝업이 더 이상 작업을 방해하지 않습니다:**
  디스크에서 rclone 구성 파일이 변경되었다는 알림이 이제 작업 중인 화면을 가로막지 않습니다.

- **엄격한 프록시 환경에서의 라이선스 등록:**
  일부 대학과 기업 프록시는 라이선스를 등록할 때 사용하는 요청 메서드를 차단합니다. 이제 등록과 등록 해제는 첫 번째
  방법이 거부되면 두 번째 방법으로 전환합니다.

- **전역 플래그 대체 처리 범위 축소:**
  전역 플래그를 적용하지 못했을 때 앱은 전체 집합을 버렸고, `--bwlimit` 같은 정상 플래그도 함께 사라졌습니다. 이제 문제를
  일으킨 플래그만 버립니다.

- **Google Photos 안내:**
  Google Photos는 이 앱에서 업로드한 사진만 나열하는데, 이는 Google이 부과한 제한입니다. 이제 빈 계정처럼 보이는 대신 앱
  안에서 이를 설명합니다. 또한 연결할 수 없을 때 앱이 직접 OAuth 클라이언트 ID를 만드는 과정을 안내합니다.

- **더 명확해진 사용자 정의 플래그 경고:**
  사용자 정의 플래그에서 `timeout`, `contimeout`, `user-agent`에 표시되는 경고 문구를 바로잡았습니다.

- **마운트 지점 선택:**
  이제 마법사는 마운트 지점을 입력하거나 찾아보는 즉시 확인하고, 사용할 수 없으면 그 이유를 표시하며 *다음*을 비활성
  상태로 유지합니다. 마지막 단계에서 실패하여 마운트 관리자에 실패한 항목이 남는 일이 없습니다. 실제로 만들 수 있는
  위치만 제안하며 `~/Mounts/<remote>`부터 제안합니다. 다른 컴퓨터의 rclone에 연결된 경우에는 그 컴퓨터의 홈 아래 폴더를
  제안합니다. *찾아보기*는 선택한 폴더 안에 리모트 이름의 폴더를 추가하고, *그 안에 새 폴더 사용*은 그대로는 사용할 수
  없는 폴더를 해결합니다. Windows에서는 마운트 폴더가 아직 존재하지 않아야 하고, macOS와 Linux에서는 비어 있어야 합니다.
  마운트 관리자도 저장하기 전에 같은 규칙을 확인하며, Windows에서는 계정이 폴더를 만들 수 없는 상위 폴더도 확인합니다.
  또한 마운트가 실패하면 *마운트 실패*만 표시하는 대신 그 이유를 보여 줍니다.

- **마법사의 대화형 데모:**
  마법사 시작 화면의 각 작업에는 *데모* 링크가 있어 브라우저에서 해당 작업의 대화형 안내를 열 수 있으며, *전체 데모*에서
  모든 데모를 볼 수 있습니다.

- **iCloud Photos:**
  첫 동기화 중에 전체 사진 수가 표시되므로 오래 걸리는 첫 실행이 멈춘 것처럼 보이지 않으며, 썸네일을 더블 클릭하여
  미리 보기에서 열 수 있습니다.

## 버그 수정

### 작업, 배치, 전송

- **S3에서 폴더 이름을 바꾸면 이전 폴더가 남았습니다:**
  배치의 이름 바꾸기 및 이동 단계가 내용은 옮겼지만 원래 폴더 마커를 그대로 남겨, 이전 폴더가 탐색기에 계속 표시되었습니다.
  오브젝트 스토리지에서 폴더는 마커 오브젝트인데, 배치 단계가 대상에 마커를 만들지도, 원본의 마커를 제거하지도 않았습니다.
  작업 관리자의 이름 바꾸기도 같은 결함이 있었고, 추가로 이전 폴더 정리를 이동과 동시에 실행하여 둘이 경합했으며,
  빈 폴더는 새 폴더가 전혀 만들어지지 않은 채 끝났습니다. 이제 둘 다 대상 마커를 만들고 원본 마커를 순서대로
  제거합니다.

- **S3와 Swift에서 이름 바꾸기 재시도:**
  폴더 이름 바꾸기를 재시도하면 원래 폴더의 빈 마커가 남았습니다.

- **재시도가 다른 작업을 실행할 수 있었습니다:**
  rclone을 재시작한 뒤 복원된 행과 현재 작업이 같은 작업 ID를 가질 수 있어서, *재시도*를 누르면 엉뚱한 작업이 다시
  실행되었습니다.

- **여러 항목의 배치 전송에서 재시도가 항상 실패했습니다:**
  여러 항목을 포함하는 배치 전송의 재시도 버튼이 한 번도 성공하지 못했습니다.

- **S3에서 멀티 스레드 스트림이 무시되었습니다:**
  *멀티 스레드 스트림* 값이 S3 대상에서는 아무 효과가 없었고, 백엔드 자체의 업로드 동시성이 우선했습니다.

- **마법사에서 중복된 작업 이름이 생성되었습니다:**
  마법사가 경로만으로 작업 이름을 만들어 두 작업의 이름이 같아질 수 있었고, 그 결과 둘 중 하나를 편집할 때 저장이
  차단되었습니다.

- **시험 실행이 실제 실행과 다른 옵션으로 미리 보기를 했습니다:**
  작업, 배치, 마법사의 시험 실행이 *Rclone 전역 플래그*를 무시하고 항상 `--transfers=4 --checkers=8`로 확인했기 때문에,
  바쁜 서버를 보호하려고 낮춘 checker 수가 미리 보기에는 적용되지 않았습니다. 배치 복사 단계의 미리 보기에는 해당 단계의
  옵션이 빠져 있었고, 필터가 아닌 사용자 정의 플래그(`--fast-list`, `--compare-dest` 등)는 모든 미리 보기에서
  누락되었으며, `--checksum`은 실제 실행과 다르게 전달되었습니다.

- **Crypt 업로드가 100%를 넘어 "실행 중"으로 남았습니다:**
  rclone은 Crypt 업로드를 암호화된 바이트로 계산하는데, 이는 파일 크기보다 약간 큽니다. 완료된 Crypt 업로드의 파일 행이
  전송 목록과 기록에서 *실행 중*으로 남았고, 실행 중에는 183% 같은 수치가 표시되었습니다.

- **동기화 알림이 다른 실행의 세부 정보를 열었습니다:**
  rclone은 시작할 때마다 작업 번호를 1부터 다시 매기므로, 완료 알림을 클릭하면 같은 번호를 재사용한 다른 실행의 원본,
  대상, 오류가 표시될 수 있었습니다.

- **삭제한 예약 배치가 계속 실행되었습니다:**
  작업 관리자에서 삭제한 예약 배치가 앱을 재시작할 때까지 일정대로 계속 실행되었습니다. 이와 함께 설정이 손상된 작업
  하나 때문에 연결 관리자가 연결을 전환하지 못하던 문제, 일정을 다시 불러오는 도중에 변경한 일정이 버려지던 문제,
  *삭제*를 빠르게 두 번 누르면 작업 관리자가 닫힐 수 있던 문제도 수정했습니다.

### 마운트

- **원격 Rclone 연결에서 마운트:**
  다른 컴퓨터의 rclone에 연결된 상태에서도 앱이 마운트 지점을 로컬 컴퓨터에서 확인하고 만들었기 때문에, Mac이나 Linux
  PC에서 마운트하면 항상 실패했습니다.

- **느린 드라이브가 "상위 폴더가 존재하지 않음"으로 보고되었습니다 (Windows):**
  상위 폴더 생성이 드라이브를 확인할 때 쓰는 것과 같은 타임아웃에 묶여 있어서, 느린 드라이브가 없는 것으로 잘못
  진단되었습니다.

- **rclone 포트가 바뀌면 저장된 마운트가 사라졌습니다:**
  내장 rclone이 다른 포트에서 시작된 뒤 저장해 둔 마운트가 목록에서 사라졌습니다.

- **얼마 후 "Too Many Open Files" 오류가 발생했습니다:**
  일부 경로에서 rclone의 응답을 끝까지 읽지 않아 매번 파일 디스크립터가 누수되었고, 결국 마운트가 완전히 동작하지
  않게 되었습니다.

- **SFTP가 서버 루트 대신 홈 디렉터리를 마운트했습니다:**
  경로 정규화가 마운트 대상의 맨 앞 슬래시를 제거하여, 서버 루트를 마운트해도 계정의 홈 디렉터리에 마운트되었습니다.

- **마운트 목록의 로컬 드라이브 이름:**
  로컬 드라이브 이름이 표시되는 방식을 수정했습니다.

- **마운트된 리모트가 "구성됨"으로 표시되었습니다:**
  Windows와 다른 컴퓨터의 rclone에 연결된 경우, 마운트된 alias 리모트, 이름이 지정된 로컬 리모트, 드라이브 문자를 가리키는
  alias가 *구성됨*으로 표시되고 *마운트* 버튼이 나타나서, 해당 행에서는 마운트를 해제할 수 없었습니다.

- **성공한 마운트 해제가 오류로 기록되었습니다:**
  마운트 해제를 두 번 하거나, 다른 곳에서 이미 해제된 것을 해제하거나, 30초가 넘게 걸리는 마운트 해제(macOS NFS 마운트는
  Finder가 볼륨을 놓아줄 때까지 기다립니다)를 하면 행이 *오류* 상태로 남았습니다. 이제 RcloneView는 마운트가 실제로
  사라졌는지 확인합니다.

- **마운트 관리자가 드라이브 문자를 누락했습니다 (Windows):**
  *로컬 경로에 마운트* 모드에서 *찾아보기*로 선택한 폴더가 드라이브 문자 없이 저장되어 *저장 후 마운트*가 실패했고,
  실패한 항목이 목록에 남았습니다.

- **폴더 선택기 앞에 오류 상자가 표시되었습니다 (Windows):**
  마운트 지점이 아직 `Auto:`인 상태에서 *로컬 폴더 찾아보기*를 누르면 폴더 선택기가 나타나기 전에 "이 프로그램을 사용하여
  이 위치를 열 수 없습니다"가 표시되었습니다.

- **로컬 디스크 탭에 드라이브 문자 마운트가 보이지 않았습니다 (Windows):**
  마법사로 마운트한 드라이브 문자가 파일 탐색기에는 나타났지만 RcloneView의 로컬 디스크 탭에는 나타나지 않았습니다. 드라이브
  문자가 나타나기 전에 탭을 새로 고쳤기 때문입니다. 이제 탭이 드라이브 문자가 나타나기를 기다립니다.

### 탐색기, 비교, 필터

- **오브젝트 이름의 백슬래시 (Windows):**
  이름에 백슬래시가 들어간 클라우드 오브젝트가 Windows 호스트에서 폴더 구분자처럼 분리되었습니다.

- **파일 이름의 백슬래시 (macOS 및 Linux):**
  경로 정규화 때문에 이름에 백슬래시가 있는 파일이 제외 규칙과 어긋났습니다.

- **필터의 이스케이프된 패턴 문자:**
  앱 자체의 필터 미리 보기가 이스케이프된 패턴 문자를 일치시키지 못해, 화면에 보이는 것과 rclone이 실제로 수행하는
  것이 달랐습니다.

- **숨겨진 Dropbox 파일이 여전히 복사되었습니다:**
  Dropbox의 숨김 파일 제외가 디렉터리를 복사할 때는 적용되지 않았습니다.

- **브라우저에 로컬 드라이브가 보이지 않았습니다 (Windows):**
  로컬 드라이브가 브라우저에 나타나지 않았습니다.

- **비교 후 발생하던 오류:**
  비교 후 작업을 실행할 때 자주 발생하던 오류를 수정했습니다.

- **열기가 항상 왼쪽 패널을 사용했습니다:**
  리모트 관리자의 *열기*가 어느 패널에서 작업 중이든 리모트를 왼쪽 패널에 놓아, 비교 중이던 화면을 대체했습니다. 이제
  활성 패널에서 열립니다.

- **rclone을 재시작하면 탐색기 탭이 닫혔습니다:**
  내장 rclone이 다른 포트로 다시 시작되었을 때(*rclone 재시작* 또는 연결 관리자에서 연결한 후)나 *Rclone 업데이트*로 버전이
  바뀌었을 때, 양쪽 패널의 모든 리모트 탭이 닫혔고 앱을 재시작해도 탭이 돌아오지 않았습니다.

### 시작, 앱 잠금, 종료, 라이선스

- **Dock 아이콘이 앱 잠금을 우회했습니다 (macOS):**
  앱이 잠긴 상태에서 Dock 아이콘을 클릭하면 비밀번호를 묻지 않고 창이 열렸습니다.

- **트레이 메뉴가 앱 잠금을 우회했습니다:**
  앱이 잠기고 트레이에 숨겨진 상태에서, 트레이의 *마운트* 항목(저장된 마운트의 마운트 또는 해제와 *모두 마운트 해제*)이
  비밀번호 없이 실행되었고, 파일 관리자에서 열도록 설정된 마운트는 폴더도 함께 열렸습니다. 창이 숨겨진 것이 아니라 최소화된
  경우에는 *열기* → 리모트가 비밀번호를 묻기 전에 탭을 추가했습니다. 이제 이 모든 동작이 먼저 비밀번호를 요청합니다.

- **트레이에서 비밀번호 입력창이 두 번 표시되었습니다 (Windows):**
  잠긴 창을 최소화한 상태에서 *열기* → 리모트나 *마운트* → *새 마운트* 같은 트레이 하위 메뉴 항목을 선택하면 비밀번호
  입력창이 두 개 열렸고, 잠금을 해제한 뒤에도 두 번째 창이 앱 위에 남아 있었으며, 거기서 *종료*를 누르면 RcloneView가
  종료되었습니다.

- **시작할 때 키링 비밀번호 요청 (Linux):**
  자동 로그인, 원격 데스크톱, 지문 로그인처럼 로그인 키링이 잠긴 채로 유지되는 환경에서 RcloneView가 창이 나타나기도 전에
  시작할 때마다 비밀번호를 요청했습니다. 관리자 권한을 요청한 것이 아니라 GNOME 키링이 잠금 해제를 요청한 것이었으며,
  이를 취소하면 앱이 멈췄습니다. 이제 RcloneView는 Linux에서 키링에 접근하지 않습니다.

- **마법사가 잠금 화면 위에 열렸습니다:**
  마법사가 *앱 잠금 비밀번호 입력* 화면 위에 나타날 수 있었습니다.

- **보조 창에서 앱 초기화:**
  보조 창의 잠금 화면에서 *앱 초기화*를 실행하면, 이미 삭제된 설정과 데이터베이스를 기반으로 메인 창이 계속 실행되었습니다.

- **"앱 종료 시 rclone 중지" 설정이 무시되었습니다:**
  macOS에서 ⌘Q나 창 닫기로 종료할 때, 그리고 잠금 화면에서 *종료* 또는 *앱 초기화*를 할 때 *앱 종료 시 rclone 중지* 설정이
  무시되었습니다.

- **rclone 재시작이 영원히 멈출 수 있었습니다:**
  구성을 변경한 뒤 rclone을 재시작할 때 이전 프로세스를 중지하라는 요청에 시간 제한이 없어서 스피너가 끝없이 도는 상태가
  될 수 있었습니다.

- **체험판 만료가 시작할 때만 확인되었습니다:**
  체험판이 만료되었는지가 프로세스가 시작될 때 한 번 결정되고 다시 평가되지 않았습니다.

- **유료 라이선스로 업그레이드한 후의 자동 마운트:**
  라이선스 검증이 끝나기 전에 확인이 실행되어, 유료 라이선스로 전환한 뒤 자동 마운트가 실행되지 않았습니다.

- **라이선스 등록 오류 메시지:**
  등록이 실패하면 이제 원인이 사용자의 언어로 표시됩니다. 응답하지 않는 서버는 예기치 않은 오류가 아니라 연결할 수 없는
  것으로 보고되며, 인터넷 연결, 방화벽, 프록시를 확인하라는 안내가 함께 표시됩니다. 유효하지 않은 키 같은 실패에는 더
  이상 프록시 안내가 나타나지 않고, 복사한 진단 정보에는 실제로 차단된 요청 메서드가 표시됩니다.

### 리모트 생성과 로그인

- **누락된 제공업체 옵션:**
  특정 제공업체에 속한 옵션이 잘못된 이름으로 필터링되어, Storj 액세스 자격 증명, Koofr 엔드포인트, 여러 Oracle 필드가
  나타나지 않았습니다.

- **필수 옵션이 고급 옵션 아래에 숨겨졌습니다:**
  필수 옵션인 *level*이 고급 옵션 아래에 숨겨져 있어서 *Compress*를 저장할 수 없었고, Oracle Object Storage도 *compartment*
  때문에 같은 방식으로 차단되었습니다.

- **Oracle 인증 방법:**
  목록에서 `no_auth` 또는 `user_principal_auth`를 선택하면 제공업체가 잘못 구성되었습니다.

- **편집한 리모트를 저장할 때 멈출 수 있었습니다:**
  기존 리모트의 변경 사항을 저장할 때 rclone 내부에서 응답하지 않을 수 있었습니다.

- **OneDrive Personal:**
  개인용 리모트를 설정할 때 근본 오류가 숨겨진 채 *연결 확인*에서 멈출 수 있었고, 드라이브 조회가 실패하면 빈 리모트가
  저장될 수 있었습니다.

- **약관 동의를 기다리는 iCloud 계정:**
  Apple의 업데이트된 약관에 동의하지 않은 계정은 `no auth method found`라는 메시지만 표시되며 실패하여 무엇이 문제인지
  알 수 없었습니다. 이제 실제 원인이 표시됩니다.

- **Google Photos 클라이언트 ID:**
  자신의 클라이언트 ID를 사용해야 한다는 요구 사항이 앱이 실제로 거치는 경로에는 적용되지 않았습니다.

### 마법사

- **마법사로 만든 작업 편집:**
  편집할 때 원본과 대상이 비어 있는 것처럼 보였고, 저장하면 그 빈 값이 실제 값을 덮어썼습니다.

- **원격 Rclone에서의 마운트 위치 (Windows):**
  다른 컴퓨터의 rclone에 연결된 동안 마법사가 마운트 위치로 로컬 컴퓨터의 홈 경로를 제안했습니다.

- **로컬 폴더를 백업 원본으로 사용 (Windows):**
  로컬 폴더를 원본으로 선택하면 오류가 발생했습니다.

- **마법사를 통한 마운트 (Windows):**
  마법사에서 마운트할 때 필요 이상으로 훨씬 자주 실패했습니다.

- **같은 리모트 이름으로 재시도:**
  로그인에 실패한 뒤 *뒤로*로 돌아가 같은 리모트 이름으로 다시 시도하면 거부되었습니다.

- **뒤로 가서 리모트 이름 바꾸기:**
  리모트를 만든 뒤 *뒤로*로 돌아가 새 이름으로 계속하면, 마법사가 닫힐 때까지 이전 리모트가 새 리모트 옆에 그대로 나열되었습니다.
  작업이 이미 실행된 경우에는 이름을 바꾸면서, 저장된 마운트, 예약된 작업, Crypt 리모트가 가리키던 리모트가 삭제되었습니다.
  이제 이전 리모트는 즉시 제거되며, 마법사가 저장한 항목 중 그 리모트를 사용하는 것이 없을 때만 제거됩니다.

- **마법사의 iCloud Photos:**
  *찾아보기*를 사용한 뒤 iCloud Photos 리모트를 추가하면 오류가 발생했습니다. 이제 iCloud Photos는 *찾아보기* 작업에서만
  제공되며, 백업, 동기화, 마운트, 비교, Crypt 작업에서는 더 이상 나열되지 않습니다. 이미 iCloud Photos를 원본으로 사용하는
  작업은 계속 실행되며, *작업 관리자*에서 새로 만들 수도 있습니다.

### 언어 및 인터페이스

- **번역되지 않은 화면:**
  언어 드롭다운 자체, Telegram 원격 제어의 두 입력란 레이블, 웹 서버 설정 섹션, iCloud Photos의 "탭이 활성화되면 자동으로
  동기화" 설정이 모든 언어에서 영어로 표시되었습니다. 일본어의 작업 삭제 확인 문구에는 작업 이름이 빠져 있었습니다.

- **설정의 스위치 행:**
  테두리가 있는 설정 섹션 안의 스위치 행에 잉크 효과가 표시되지 않았고 디버그 어서션이 발생했습니다.

- **터미널의 도움말 팝업:**
  터미널에 디렉터리 이름을 입력하면 명령으로 처리되어 도움말 팝업이 나타났습니다.

- **버전 정보 (Windows):**
  RcloneView에 표시되는 버전 정보를 수정했습니다.

- **데이터베이스 폴더를 바꾸면 저장이 되지 않았습니다:**
  설정에서 *데이터베이스 폴더*를 변경한 뒤 앱을 재시작하기 전까지 작업, 마운트, 기록의 모든 저장과 조회가 실패했습니다.

### 패키징 및 업데이트

- **Linux의 번들 Rclone:**
  Linux 패키지는 빌드 머신에 있던 아무 rclone으로 빌드되어 rclone 1.60.1 개발 빌드가 포함될 수 있었습니다. 이제 Linux
  빌드도 다른 플랫폼과 같은 고정된 rclone을 번들합니다.

- **업데이트가 기존 deb/rpm 설치에 반영되지 않았습니다:**
  저장된 rclone 경로가 번들 바이너리보다 우선하여, 업데이트 후에도 번들 rclone이 적용되지 않았습니다.

- **"Rclone 업데이트"가 항상 실패하면서 성공으로 보고되었습니다 (Linux):**
  번들 rclone을 제자리에서 업데이트하는 것은 일반 사용자 계정으로는 성공할 수 없었지만, 앱이 터미널의 종료 코드로 결과를
  판단했기 때문에 성공했다고 보고했고, 이 시도로 인해 진행 중이던 전송이 중단되었습니다.

- **"Rclone 업데이트"가 사용자 소유의 Rclone을 거부했습니다 (Linux):**
  *내장 Rclone 위치*가 사용자 계정이 소유한 rclone을 가리키는데도 *Rclone 업데이트*가 번들 rclone과 같은 "쓸 수 없음"
  알림을 표시하고 시도하지 않아서, Linux에서는 앱에서 rclone을 아예 업데이트할 수 없었습니다. 이제 사용자가 소유한
  rclone은 업데이트되며, 번들 rclone은 여전히 패키지에 맡깁니다.

- **aarch64 RPM을 설치할 수 없었습니다:**
  aarch64 rpm이 Rockchip 전용 라이브러리(`librockchip_mpp`)를 요구 사항으로 나열하여, 이를 제공하지 않는 Fedora와 다른
  배포판에서는 `dnf install`이 설치를 거부할 수 있었습니다.

- **조용히 넘어가던 빌드 실패:**
  설치 프로그램 단계가 실패한 빌드가 Windows와 macOS 모두에서 성공한 것처럼 게시될 수 있었습니다. 이제 해당 스크립트는
  실패를 분명하게 알립니다.
