# RcloneView 1.6 – 版本說明

**發布日期：** 2026 年 10 月<br/>
**支援平台：** Windows、macOS、Linux

RcloneView 1.6 是一個專注於正確性的版本。兩種會導致檔案遺失的情況與一個對外開放的網路連接埠已被封堵，您在工作中輸入的旗標現在會確實傳送給 rclone，失敗的同步不會再回報自己已完成，RcloneView 也不再關閉不屬於它的 rclone 程序。1.6 的後續更新還會阻止密碼錯誤的遠端不斷重複登入、直到伺服器封鎖這台電腦，並阻止排程工作在每個開啟的視窗中各執行一次。除此之外，本版本也修正了掛載、檔案總管、建立遠端、精靈，以及三個平台上封裝方面的大量問題。

## 升級前請先閱讀

- **工作的自訂旗標中的篩選旗標現在會生效。**
  在工作的 *自訂旗標* 欄位中輸入的篩選旗標，例如 `--include`、`--exclude` 和 `--filter`，在工作執行前會被丟棄——
  它們只會在試運行與 bisync 診斷期間套用，因此預覽與實際執行的結果可能不一致。現在這些旗標在所有路徑上都會傳遞。<br/>
  **這會改變現有工作的行為。** 如果您有在自訂旗標中設定篩選條件的工作，它現在只會傳輸符合條件的檔案，
  而不是全部檔案。對於啟用刪除的 *同步* 工作，這也會改變目的地上被刪除的內容。請檢查所有在自訂旗標中保留篩選條件的工作，
  並在讓它依排程執行之前，先以 *試運行* 執行一次。

- **密碼為長權杖的遠端需要重新輸入一次密碼。**
  儲存遠端時，RcloneView 會讓 rclone 自行判斷收到的密碼是否仍需要編碼。對於看起來像 base64 的密碼，這個判斷一律是錯的，
  因此該值會以未編碼的形式寫入設定，並在每次連線嘗試時被打亂。以這種方式儲存的遠端從來無法完成驗證。
  RcloneView 現在會自行為密碼編碼，因此從此版本起您新增或編輯的任何內容都會被正確儲存。<br/>
  **已經以這種方式儲存的遠端不會因更新而被修復。** 這只影響長度達 22 個字元以上、且完全由字母、數字、`-` 和 `_` 組成的密碼——
  實際上是 API 權杖或自動產生的應用程式密碼，而不是您自己選擇的密碼。如果您有遠端一直因驗證錯誤而無法連線，
  請在 *遠端管理器 → 編輯* 中開啟它，重新輸入密碼並儲存。之後它就能連線了。<br/>
  **請勿重新輸入目前可正常開啟的 Crypt 遠端的密碼。** 以這種方式儲存的 Crypt 遠端從未失敗：
  其中的檔案是以被打亂後的值加密的，也只有該值能將它們讀回。現在輸入真正的密碼會讓該遠端改用另一把金鑰，
  其中既有的檔案將無法再開啟。請保持這類遠端原樣——編輯它的其他設定是安全的。如果您已經重新輸入密碼，
  而檔案因此無法開啟，請將舊的值放回 `rclone.conf`：那就是密碼本身，只是未經編碼寫入。若要將這類遠端改用其真正的密碼，
  請先透過現有的遠端將檔案複製出來，再重新建立該遠端。

- **啟用應用程式鎖定時，必須先解鎖應用程式才會啟動任何項目。**
  鎖定畫面現在會先於任何視窗內容出現，而 rclone、排程工作、自動掛載與網頁伺服器都會等待密碼，而不是在鎖定畫面背後啟動。
  如果 RcloneView 在登入時啟動且已啟用應用程式鎖定，則在有人解鎖之前，排程工作與自動掛載都不會執行。
  如果這台電腦依賴工作或掛載在重新啟動後無人值守地執行，請關閉應用程式鎖定，或在每次登入後解鎖應用程式。

- **登入遭拒絕的遠端不再被自動連線。**
  對於以密碼登入的遠端——SFTP、FTP、WebDAV 與 SMB——RcloneView 現在會檢查登入一次，若伺服器拒絕，
  就會停止連線到該遠端：不自動掛載、不執行排程工作、不重新開啟其分頁。這個狀態會在重新啟動後保留。
  使用此類遠端的排程工作會被記錄為失敗，並發送一般的失敗通知。在檔案總管中按下 *重試*，或在 *編輯遠端* 中儲存更正後的密碼，
  即可恢復連線。<br/>
  **如果伺服器只是暫時拒絕登入**——例如其密碼正在變更期間——該遠端上的排程工作之後會持續暫停，直到有人按下 *重試*。
  透過瀏覽器或金鑰登入的雲端儲存不受影響。

- **排程工作現在只會從主視窗執行。**
  排程會跟隨主視窗的 rclone 連線。如果您只將次要視窗切換到另一個連線，則在該視窗開啟期間，該連線的排程工作不會執行；
  請改為在主視窗中選擇該連線。如果主視窗意外關閉，即使其他視窗仍然開啟，排程工作也會停止，直到 RcloneView 重新啟動。

## 資料遺失與安全性

- **部分刪除失敗後重試，可能清除上層資料夾：**
  一次刪除多個檔案、其中部分失敗，然後按下 *重試*，可能會移除整個上層資料夾，而不是重試失敗的檔案。
  現在重試只會作用於失敗的項目。

- **檔名含有 `[` `]` `*` `?` `{` 可能刪除錯誤的檔案：**
  刪除多個檔案時，其路徑未經跳脫就交給 rclone 的篩選引擎，因此包含模式字元的名稱會被當作萬用字元處理。
  一次單檔刪除可能比對到並移除其他資料夾中的檔案。現在路徑在作為篩選條件使用之前會先經過跳脫。

- **以既有名稱建立遠端會取代該遠端：**
  rclone 將「建立」視為「建立或更新」，因此以已被使用的名稱建立遠端——即使儲存類型不同——
  也會在沒有任何提示的情況下覆寫既有遠端的設定與憑證。新建遠端對話框、精靈，以及精靈的 Crypt 步驟，
  現在會在您輸入已被使用的名稱時立即提出警告，且不會繼續。

- **視窗間通訊連接埠曾對網路開放：**
  RcloneView 用於自身視窗之間通訊的連接埠（13542）曾監聽所有網路介面，而不是僅限這台機器，且主視窗接受空白的驗證金鑰。
  現在它只繫結到本機，並且需要有效的金鑰。

## 重點功能

- **RcloneView 不再停止您的其他 rclone 程序：**
  結束應用程式、重新啟動 rclone，或執行 *更新 Rclone* 時，會依名稱終止 rclone，這也會殺掉這台機器上的所有其他 rclone——
  例如您在終端機中啟動的 `rclone mount`、cron 工作，或其他使用 rclone 的工具。
  現在 RcloneView 只會停止它自己啟動的程序。

- **密碼錯誤不再讓這台電腦被封鎖：**
  一個密碼錯誤的 SFTP 遠端可能登入數十次，直到 NAS 封鎖了這台電腦的 IP 位址。
  rclone 對每個請求最多會重試被拒絕的登入十次，開啟單一分頁就會同時送出數個請求，
  而應用程式還會對失敗的清單再重試三次——一個分頁大約就有 80 次登入。應用程式還會在啟動時、還原分頁時、
  自動掛載時，以及排程工作時自行連線。對於以密碼登入的遠端（SFTP、FTP、WebDAV、SMB），RcloneView 現在會檢查登入一次，
  若被拒絕就停止。檔案總管會顯示 *登入失敗*，並附有 *編輯遠端* 與 *重試* 按鈕——對於 Crypt 或 alias 遠端，
  則會指向其底層的遠端——而遠端管理器會顯示 *登入失敗* 標記，取代可用空間。在 *新建遠端* 中以錯誤密碼新增的遠端不會被儲存。
  當伺服器在多次失敗後停止回應時，檔案總管現在會在數秒內告知 IP 可能已被封鎖，而不是轉圈約 50 秒。

- **排程工作在每個開啟的視窗中各執行一次：**
  每個 RcloneView 視窗都會執行自己的排程器，因此開啟第二個視窗時，每個排程工作與批次都會在同一時刻於各視窗各啟動一次。
  兩份副本寫入同一個本機資料夾時，會互相刪除對方的部分檔案，執行結果可能是什麼都沒有複製。
  在次要視窗中變更或刪除排程，也會讓主視窗繼續觸發舊的排程。現在排程只會從主視窗執行，
  在其他視窗中所做的變更會傳遞給它。在排程觸發的瞬間按下 *運行*，或快速連按兩次，同樣可能讓同一個工作啟動兩次；
  現在它只會啟動一次。

- **升級前的 Rclone 仍持續執行：**
  上一個版本遺留的 rclone 在升級 RcloneView 後仍被重複使用，因此在該程序被手動停止之前，新內建的 rclone 不會被使用。
  現在當執行中的版本不同時，RcloneView 會重新啟動 rclone。它也不再把碰巧使用 rclone 連接埠的其他程式誤認為 rclone
  ——那曾使應用程式只顯示 *無連線*——而是改在下一個可用的連接埠上啟動 rclone。在結束或重新啟動 rclone 時，
  應用程式現在會等待 rclone 自行關閉；以前它每次都會強制終止，導致掛載尚未卸載、VFS 快取也尚未清理。

- **自訂旗標與全域旗標確實被套用：**
  您設定的旗標曾以數種不同方式被悄悄丟棄，這就是為什麼在命令列上有效的旗標，在應用程式中看起來沒有任何作用。
  本版本已修正：設定中的全域 rclone 旗標未套用於同步／複製工作；放入工作自訂旗標的後端旗標與全程序旗標被忽略；
  批次步驟欄位（頻寬限制、Include、Min/Max age、Min/Max size）以 rclone 會丟棄的形式傳送；以數字撰寫的布林旗標
  （`--checksum=1`，在命令列上有效）會使整個請求失敗，導致工作從未啟動；重複的 `--backup-dir` 與 `--compare-dest`
  旗標被拒絕；`--header`、`--header-upload`、`--header-download` 與 `--compare-dest` 被轉換成錯誤的類型；
  旗標解析器無法處理值內的引號或空格；試運行完全不包含自訂旗標，因此預覽與實際執行不符；
  以及全域旗標欄位中的一個錯誤字元會悄悄丟棄所有旗標，而不只是有問題的那一個。

- **失敗的同步不再回報「無變更」：**
  在傳輸任何內容之前就失敗的同步——憑證錯誤、遠端無法連線、路徑不存在——
  在工作清單、歷史記錄與通知中都被顯示為沒有任何變更的已完成執行。現在會讀取 rclone 為該工作回報的錯誤，
  因此失敗會被顯示為失敗。

- **清單失敗不再被視為空資料夾：**
  當資料夾無法列出內容時，應用程式的多個部分會直接假設它是空的。這就是掛載可能被放在既有內容之上、
  掛載的 *驗證* 永遠通過，以及資料夾樹狀結構、比較與路徑選擇器可能對一個裝滿檔案的資料夾完全不顯示任何內容的原因。
  現在失敗的清單會被回報為失敗——清單檢視也會顯示它，而不是看起來像空資料夾。

- **中途放棄的登入曾阻擋所有新遠端：**
  在未完成的情況下關閉服務供應商的登入頁面，會使 rclone 的授權輔助程式持續佔用連接埠 53682，
  之後每一次建立需透過瀏覽器登入的遠端的嘗試都會失敗。重新啟動應用程式並不會釋放它——
  唯一的出路是強制結束 rclone。現在當登入被放棄時，該輔助程式會被關閉。

## 新功能與改進

- **每個工作的上傳並行數：**
  後端上傳並行數（`upload_concurrency`）現在可以針對單一工作設定，而不僅限於全域設定，
  因此對應快速遠端的工作不必與其他所有項目共用同一個設定。

- **新遠端直接在面板中開啟：**
  建立遠端之後，它現在會立即在檔案總管面板中開啟，而不需要您自己去尋找並開啟。

- **在檔案總管中顯示可用空間：**
  對於能夠回報的遠端，檔案總管中現在會顯示遠端的剩餘空間。

- **從比較檢視複製更快：**
  從比較檢視複製時，每個項目都會啟動一個 rclone 工作，且無論 `--transfers` 設定為多少，都一次只執行四個。
  現在項目會依每個遠端與上層資料夾分組為一個同步／複製，並遵循您的 `--transfers` 設定。

- **「設定檔已變更」彈出視窗不再打斷操作：**
  rclone 設定檔在磁碟上已變更的通知，不再於您操作到一半時佔滿畫面。

- **嚴格代理伺服器後的授權註冊：**
  部分大學與企業的代理伺服器會封鎖用於註冊授權的請求方法。現在註冊與取消註冊在第一種方法被拒絕時，會改用第二種方法。

- **全域旗標的後備處理範圍更小：**
  當全域旗標無法套用時，應用程式過去會丟棄整組旗標——連同 `--bwlimit` 等原本可用的旗標一起丟棄。
  現在只會丟棄造成問題的那個旗標。

- **Google Photos 指引：**
  Google Photos 只會列出由此應用程式上傳的照片，這是 Google 施加的限制——現在應用程式中會對此加以說明，
  而不是看起來像一個空的帳戶。當無法建立連線時，應用程式也會引導您建立自己的 OAuth 用戶端 ID。

- **更清楚的自訂旗標警告：**
  自訂旗標中針對 `timeout`、`contimeout` 與 `user-agent` 顯示的警告文字已經修正。

- **選擇掛載點：**
  精靈現在會在您輸入或瀏覽到掛載點時立即檢查它，在無法使用時顯示原因，並讓 *下一步* 保持停用——
  而不是在最後一步才失敗，並在掛載管理員中留下一筆失敗的項目。它只會建議實際可以建立的位置，並以 `~/Mounts/<remote>` 優先；
  當連線到另一台機器上的 rclone 時，它會建議該機器家目錄下的資料夾。*瀏覽* 會在您選擇的資料夾內新增一個以遠端命名的資料夾，
  而 *使用其中的新資料夾* 可修正無法直接使用的資料夾——在 Windows 上掛載資料夾必須尚不存在，在 macOS 與 Linux 上則必須是空的。
  掛載管理員在儲存前會檢查相同的規則，包括在 Windows 上您的帳戶無法在其中建立資料夾的上層資料夾，
  並會顯示掛載失敗的原因，而不是只顯示 *掛載失敗*。

- **來自精靈的互動式導覽：**
  精靈歡迎畫面上的每項任務都有一個 *導覽* 連結，可在瀏覽器中開啟該任務的互動式逐步導覽，*所有導覽* 則列出全部導覽。

- **iCloud Photos：**
  首次同步期間現在會顯示照片總數，因此較長的首次執行不再看起來像是停滯，並且按兩下縮圖即可在預覽中開啟。

## 錯誤修正

### 工作、批次與傳輸

- **在 S3 上重新命名資料夾會留下舊資料夾：**
  批次中的重新命名與移動步驟會移動內容，卻把原始資料夾標記留在原處，因此舊資料夾仍持續出現在檔案總管中。
  在物件儲存上，資料夾是一個標記物件，而批次步驟從未在目的地建立標記，也沒有移除來源處的標記。
  作業管理器中的重新命名有相同的缺漏，並且還會在移動的同時執行舊資料夾的清理，使兩者互相競爭；
  空資料夾最終完全不會建立新資料夾。現在兩者都會依序建立目的地標記並移除來源標記。

- **在 S3 與 Swift 上重試重新命名：**
  重試資料夾重新命名會為原始資料夾留下一個空的標記。

- **重試可能執行不同的工作：**
  rclone 重新啟動後，還原的資料列與目前的工作可能共用相同的工作 ID，因此按下 *重試* 會重新執行錯誤的工作。

- **多項目批次傳輸的重試一律失敗：**
  涵蓋多個項目的批次傳輸上的重試按鈕從未成功。

- **S3 上的多執行緒串流被忽略：**
  *多線程傳輸數量* 的值對 S3 目的地沒有任何作用，而是以後端自身的上傳並行數為準。

- **精靈產生重複的工作名稱：**
  精靈僅以路徑建立工作的名稱，因此兩個工作可能最終使用相同的名稱——而這又會在您編輯其中任何一個時阻止儲存。

- **試運行預覽使用的選項與實際執行不同：**
  工作、批次或精靈的試運行會忽略 *全域 Rclone 參數*，並一律以 `--transfers=4 --checkers=8` 進行檢查，
  因此為了減輕忙碌伺服器負擔而調低的檢查器數量不會套用於預覽。批次複製步驟的預覽遺漏了該步驟的選項，
  篩選條件以外的自訂旗標（例如 `--fast-list` 與 `--compare-dest`）在所有預覽中都缺席，
  而 `--checksum` 的傳遞方式也與實際執行不同。

- **Crypt 上傳停留在「運行中」並超過 100%：**
  rclone 以加密後的位元組計算 Crypt 上傳，這比檔案大小略多。已完成的 Crypt 上傳的檔案資料列，
  在傳輸清單與歷史記錄中停留在 *運行中*，並且在執行時顯示 183% 之類的數字。

- **同步通知開啟了另一次執行的詳細資料：**
  rclone 每次啟動時都會從 1 重新為其工作編號，因此點擊完成通知時，可能顯示重複使用相同編號的另一次執行的來源、目的地與錯誤。

- **已刪除的排程批次仍持續執行：**
  在作業管理器中刪除的排程批次，在應用程式重新啟動之前仍會依排程執行。另外也已修正：
  一個設定損毀的工作會使連線管理員無法切換連線；在重新載入排程期間所做的排程變更會被丟棄；
  以及快速連按兩次 *刪除* 可能會關閉作業管理器。

### 掛載

- **從遠端 Rclone 連線掛載：**
  當連線到另一台機器上的 rclone 時，應用程式仍在本機上檢查並建立掛載點，因此從 Mac 或 Linux PC 掛載一律失敗。

- **速度慢的磁碟機被回報為「上層資料夾不存在」（Windows）：**
  建立上層資料夾與探測磁碟機所用的逾時綁在一起，因此速度慢的磁碟機被誤判為不存在。

- **Rclone 連接埠變更時，已儲存的掛載消失：**
  內嵌的 rclone 改用不同連接埠啟動後，您已儲存的掛載從清單中消失。

- **一段時間後出現「Too Many Open Files」：**
  rclone 的回應在某些路徑上未被完整讀取，每次都會洩漏一個檔案描述元，直到掛載完全無法運作為止。

- **SFTP 掛載了家目錄，而不是伺服器根目錄：**
  路徑正規化會去除掛載目標開頭的斜線，因此掛載伺服器根目錄的結果落在帳戶的家目錄上。

- **掛載清單中的本機磁碟機名稱：**
  修正了本機磁碟機名稱的顯示方式。

- **已掛載的遠端被列為「已設定」：**
  在 Windows 上，以及連線到另一台機器上的 rclone 時，已掛載的 alias 遠端、具名的本機遠端，或指向磁碟機代號的 alias
  會被列為 *已設定* 並附有 *掛載* 按鈕，因此無法從其資料列卸載。

- **成功的卸載被記錄為錯誤：**
  卸載兩次、卸載已在別處卸載的項目，或卸載耗時超過 30 秒——macOS 的 NFS 掛載會等待 Finder 放開該磁碟區——
  都會使資料列停在 *錯誤*。現在 RcloneView 會檢查掛載是否確實已經消失。

- **掛載管理員遺漏磁碟機代號（Windows）：**
  在 *掛載到本地路徑* 模式下，以 *瀏覽* 選擇的資料夾會在沒有磁碟機代號的情況下被儲存，因此 *儲存並掛載* 失敗，
  失敗的項目仍留在清單中。

- **資料夾選擇器前出現錯誤訊息方塊（Windows）：**
  當掛載點仍為 `Auto:` 時按下 *瀏覽本機資料夾*，在資料夾選擇器之前會顯示「You can't open this location using this program」。

- **磁碟機代號掛載未出現在本機磁碟分頁（Windows）：**
  透過精靈掛載的磁碟機代號會出現在檔案總管中，卻不出現在 RcloneView 的本機磁碟分頁，
  因為該分頁在磁碟機代號出現之前就已重新整理。現在該分頁會等待它出現。

### 檔案總管、比較與篩選

- **物件名稱中的反斜線（Windows）：**
  在 Windows 主機上，名稱含有反斜線的雲端物件會被當作資料夾分隔符號而分割。

- **檔名中的反斜線（macOS 與 Linux）：**
  路徑正規化使名稱含有反斜線的檔案與排除規則不一致。

- **篩選條件中跳脫的模式字元：**
  應用程式自己的篩選預覽無法比對跳脫過的模式字元，因此您在畫面上看到的與 rclone 實際執行的結果不同。

- **隱藏的 Dropbox 檔案仍被複製：**
  複製目錄時，針對 Dropbox 隱藏檔案的排除規則沒有生效。

- **本機磁碟機未出現在瀏覽器中（Windows）：**
  本機磁碟機沒有出現在瀏覽器中。

- **使用比較後出現錯誤：**
  修正了在比較之後執行操作時頻繁出現的錯誤。

- **開啟一律使用左側面板：**
  遠端管理器中的 *打開* 會不論您正在哪個面板操作，一律將遠端放在左側面板，取代了您正在比較的檢視。
  現在它會在使用中的面板開啟。

- **Rclone 重新啟動時檔案總管分頁被關閉：**
  當內嵌的 rclone 以不同連接埠恢復運作——在 *重新啟動rclone* 或從連線管理員連線之後——或是 *更新 Rclone* 變更了其版本時，
  兩個面板中的每個遠端分頁都會被關閉，而且重新啟動應用程式後這些分頁也不會恢復。

### 啟動、應用程式鎖定、結束與授權

- **Dock 圖示繞過了應用程式鎖定（macOS）：**
  在應用程式鎖定時點擊 Dock 圖示，會在不詢問密碼的情況下開啟視窗。

- **系統匣選單繞過了應用程式鎖定：**
  當應用程式被鎖定並隱藏在系統匣時，系統匣的 *掛載* 項目——掛載或卸載已儲存的掛載，以及 *全部卸載*——
  都會在不需要密碼的情況下執行，而設定為在檔案管理員中開啟的掛載也會一併開啟其資料夾。
  當視窗是最小化而非隱藏時，*打開* → 遠端會在詢問密碼之前就新增分頁。現在這些都會先詢問。

- **系統匣出現兩次密碼提示（Windows）：**
  在鎖定的視窗已最小化的情況下，選擇系統匣子選單項目，例如 *打開* → 遠端或 *掛載* → *新掛載*，會開啟兩個密碼提示；
  解鎖之後，第二個仍停留在應用程式上方，並且在其中按下 *退出* 會結束 RcloneView。

- **啟動時的鑰匙圈密碼提示（Linux）：**
  在登入鑰匙圈始終保持鎖定的環境——自動登入、遠端桌面、指紋登入——RcloneView 在每次啟動時、視窗出現之前都會要求輸入密碼。
  那是 GNOME 鑰匙圈要求解鎖，而不是要求管理員權限，而且取消它會使應用程式當機。
  RcloneView 在 Linux 上不再碰觸鑰匙圈。

- **精靈開啟在鎖定畫面之上：**
  精靈可能出現在 *應用程式鎖定密碼* 畫面之上。

- **從次要視窗重設應用程式：**
  從次要視窗的鎖定畫面執行 *重設應用程式*，會讓主視窗繼續使用已被清除的設定與資料庫運作。

- **「退出應用時停止 rclone」被忽略：**
  在 macOS 上以 ⌘Q 或關閉視窗結束，以及從鎖定畫面執行 *退出* 或 *重設應用程式*，都會忽略 *退出應用時停止 rclone* 設定。

- **重新啟動 Rclone 可能永遠卡住：**
  在設定變更後重新啟動 rclone，可能停在無止境的轉圈，因為停止舊程序的請求沒有時間限制。

- **試用期到期只在啟動時檢查：**
  試用期是否已到期，是在程序啟動時決定一次，之後就不再重新評估。

- **升級為付費授權後的自動掛載：**
  切換為付費授權後，自動掛載沒有執行，因為檢查在授權驗證完成之前就已進行。

- **授權註冊錯誤訊息：**
  當註冊失敗時，現在會以您的語言顯示原因。伺服器沒有回應時會被回報為無法連線，並提醒您檢查網際網路連線、防火牆與代理伺服器，
  而不是回報為非預期的錯誤。像金鑰無效這類失敗不再出現代理伺服器的建議，且複製的診斷資訊會指出實際被封鎖的請求方法。

### 建立遠端與登入

- **缺少服務供應商專屬選項：**
  屬於特定服務供應商的選項曾以錯誤的名稱篩選，因此 Storj 存取憑證、Koofr 端點，以及數個 Oracle 欄位從未出現。

- **必要選項被隱藏在進階選項下：**
  *Compress* 無法儲存，因為其必要的 *level* 選項被隱藏在進階選項下，而 Oracle Object Storage 也同樣被 *compartment* 阻擋。

- **Oracle 驗證方式：**
  從清單中選擇 `no_auth` 或 `user_principal_auth` 會使服務供應商被錯誤設定。

- **儲存已編輯的遠端可能卡住：**
  儲存對既有遠端的變更時，可能在 rclone 內部停止回應。

- **OneDrive 個人版：**
  設定個人遠端時可能停在 *驗證連線*，且底層錯誤被隱藏，而磁碟機查詢失敗時可能儲存一個空的遠端。

- **等待條款的 iCloud 帳戶：**
  尚未接受 Apple 更新條款的帳戶只會以 `no auth method found` 失敗，無從得知問題出在哪裡。現在會顯示真正的原因。

- **Google Photos 用戶端 ID：**
  必須使用自己的用戶端 ID 的要求，並未套用在應用程式實際採用的路徑上。

### 精靈

- **編輯由精靈建立的工作：**
  編輯時來源與目的地看起來是空的，而儲存時會用那些空值覆寫真正的值。

- **使用遠端 Rclone 時的掛載位置（Windows）：**
  當連線到另一台機器上的 rclone 時，精靈建議了本機上的家目錄路徑作為掛載位置。

- **以本機資料夾作為備份來源（Windows）：**
  選擇本機資料夾作為來源時會出現錯誤。

- **透過精靈掛載（Windows）：**
  從精靈掛載失敗的頻率遠高於應有的程度。

- **以相同遠端名稱重試：**
  登入失敗後，按 *返回* 並以相同的遠端名稱再試一次會被拒絕。

- **以「返回」重新命名遠端：**
  建立遠端後按 *返回* 並以新名稱繼續，會讓舊的遠端與新的遠端並列在清單中，直到精靈關閉為止。
  如果任務已經執行過，重新命名會刪除已儲存的掛載、排程工作或 Crypt 遠端所指向的遠端。
  現在較早的遠端會立即被移除，且僅在精靈儲存的任何項目都沒有使用它時才會移除。

- **精靈中的 iCloud Photos：**
  在使用 *瀏覽* 後新增 iCloud Photos 遠端會出現錯誤。現在 iCloud Photos 只會在 *瀏覽* 任務中提供；
  備份、同步、掛載、比較與 Crypt 任務不再列出它。已將 iCloud Photos 作為來源的工作會繼續執行，
  您仍可在 *作業管理器* 中建立這類工作。

### 封裝與更新

- **Linux 上內建的 Rclone：**
  Linux 套件是以建置機器上碰巧存在的 rclone 建置的，可能會附帶 rclone 1.60.1 的開發版本。
  現在 Linux 版本與其他平台一樣，內建相同的固定版本 rclone。

- **更新未送達現有的 deb/rpm 安裝：**
  已儲存的 rclone 路徑優先於內建的二進位檔，因此更新之後內建的 rclone 從未生效。

- **「更新 Rclone」一律失敗卻回報成功（Linux）：**
  在一般使用者帳戶下，就地更新內建的 rclone 無法成功，但應用程式仍回報成功，
  因為它是以終端機的結束代碼判斷結果——而且這次嘗試還中斷了進行中的傳輸。

- **「更新 Rclone」拒絕您擁有的 Rclone（Linux）：**
  當 *本地 Rclone 位置* 指向由您的帳戶擁有的 rclone 時，*更新 Rclone* 會顯示與內建版本相同的「無法寫入」通知，且從未嘗試，
  因此在 Linux 上完全無法從應用程式更新 rclone。現在您所擁有的 rclone 會被更新；內建的仍留給套件處理。

- **aarch64 RPM 無法安裝：**
  aarch64 的 rpm 將僅限 Rockchip 的函式庫（`librockchip_mpp`）列為相依項目，因此 `dnf install` 在 Fedora
  與其他未提供該函式庫的發行版上可能會拒絕安裝。

- **無聲的建置失敗：**
  在 Windows 與 macOS 上，安裝程式步驟失敗的建置仍可能被當作成功而發布。現在這些指令碼會明確失敗。
