# 人力資源與招聘機構的雲端儲存 — 使用 RcloneView 管理應徵者檔案

> 招聘機構的成敗取決於能多快找到、共享並保護應徵者檔案 — RcloneView 讓所有履歷、合約與背景調查資料在雲端保持井然有序。

人力資源或招聘機構會持續產生大量文件:履歷、錄取信、已簽署的合約、背景調查報告、工時表與客戶資料表。再加上各分公司或招聘顧問各自偏好不同的雲端儲存供應商,檔案分散便成為每日的營運風險。RcloneView 為機構提供一個統一視窗,可跨所有正在使用的雲端帳戶瀏覽、傳輸與備份應徵者檔案,而不必強制遷移到單一供應商。

## 在單一畫面檢視所有分公司的雲端帳戶

招聘團隊很少會自然而然地統一使用單一儲存供應商 —— 某間分公司可能因為與 Microsoft 365 綁定而使用 OneDrive,而另一個團隊則依賴 Google Drive 或 Dropbox 來與應徵者共享文件。透過 RcloneView 的多面板檔案總管,合規或營運負責人可以並排開啟多個遠端連線,瀏覽各分公司的應徵者資料夾,並在不切換瀏覽器分頁與帳號登入的情況下移動檔案。與僅支援掛載的工具不同,RcloneView 在 FREE 授權下也支援同步與資料夾比較,因此瀏覽檔案的同一視窗也能維持各分公司封存資料的一致性。

<img src="/support/images/en/blog/new-remote.png" alt="Adding a new cloud storage remote in RcloneView" class="img-large img-center" />

## 讓應徵者記錄保持備份與最新狀態

遺失一份已簽署的合約或背景調查報告不僅僅是不便 —— 它可能造成合規缺口。RcloneView 的同步工作負責將工作資料夾單向備份到封存遠端,並提供 Dry Run 功能,可在實際執行前預覽將要複製或刪除的內容。對於應徵者數量龐大的機構,1:N 同步可以將單一來源資料夾 —— 例如共享的「Active Candidates」目錄 —— 同時鏡射到多個目標位置,自動保持即時副本與冷備份的同步狀態。

<img src="/support/images/en/blog/cloud-to-cloud-transfer-default.png" alt="Syncing candidate files between cloud storage accounts in RcloneView" class="img-large img-center" />

## 無需手動操作即可排程例行封存

在招聘旺季,錄取相關文件往往會迅速累積,而手動封存已完成的應徵者資料夾很容易被無限期拖延。RcloneView 的 Job Manager 在 PLUS 授權下支援排程同步工作,因此每晚或每週執行的工作可以自動將已完成的應徵者檔案從使用中的工作區移動到長期儲存,而 Job History 會準確記錄執行內容與時間,以利稽核。

<img src="/support/images/en/howto/rcloneview-advanced/create-job-schedule.png" alt="Creating a scheduled sync job in RcloneView" class="img-large img-center" />

## 開始使用

1. 從 [rcloneview.com](https://rcloneview.com/src/download.html) **下載 RcloneView**。
2. 在 Remote Manager 中將每間分公司的雲端儲存帳戶連線為個別的遠端。
3. 設定從使用中的應徵者資料夾到備份遠端的同步工作,並先執行 Dry Run 確認檔案清單。
4. 新增排程(PLUS 授權),讓已完成的應徵者記錄自動移動到封存儲存空間。

對招聘機構而言,井然有序且已備份的應徵者檔案不僅僅是良好實務 —— 它是順利通過稽核與陷入混亂之間的分水嶺。
